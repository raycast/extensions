# Pouch owns a dedicated Discovery Package listing

The Pouch needs a dedicated Package that loads Tools, Skills, and Skill Contents. Kent's `raycast` listing is a generic launcher kit, so a fork of that listing is the wrong product identity. Publish `@cameronpak/raycast-kodys-pouch` (`kody.id` `raycast-kodys-pouch`) as a Community Listing: a pinned snapshot installers fork and publish. The extension default discovery id matches. The author's old `raycast` fork is hidden.

Kody retired package invocation tokens in favor of inbound webhooks. The Discovery Package declares one `sync`, `params` webhook named `pouch`. Its closed operation union delegates only to the five read-only exports the extension needs; it is not an arbitrary export router. Installers mint that credential URL on their own published fork and store it in one Raycast password preference. Contents load through the webhook's `get-skill` operation, not directly through `skills/skill-get`. The `get-skill` package export remains available for generated Mentions loaded through agent execute.
