## Input and result details

- `projectId` is a numeric project ID. If omitted, the client resolves a configured default from environment, credentials configuration, or extension preferences. All calls use the configured host; no tool accepts a host or API key. Authentication accepts only personal keys beginning with `phx_`. `whoami` has no input and returns compact user and organization details.
- `list-projects` defaults to 50 records, capped at 200, and returns `projects`, `count`, and `next`. Project records include numeric `id`, name, UUID, timezone, and organization. Every list tool exposes `next` but none accepts a cursor, offset, or next URL.
- `query-hogql` accepts SQL beginning with SELECT or WITH and posts a `HogQLQuery`. It accepts no typed-query body, parameters, dashboard context, or bound filter/variable values. Use read-only SQL with explicit predicates. It polls unfinished responses with a query ID up to 30 times at one-second intervals; failures and polling exhaustion throw. There is no separate query-status tool for continuing later.
- Query output contains `projectId`, `columns`, `types`, `rows`, `rowCount`, `returnedRows`, `truncated`, `queryId`, and `status`. `status` can be absent on synchronous responses. `maxRows` defaults to 100 and caps at 1,000; `maxCellLength` defaults to 500 and caps at 5,000. These apply after fetching the server response. `rowCount` is the length of that response's results array, not the number of matching events or people. `truncated` reports only local row slicing, not server query limits, cell truncation, or completeness. Give every selected column a unique alias because duplicate names overwrite earlier values when rows become objects.
- The client normalizes absent result arrays to an empty array when it cannot poll, and does not expose the server's `complete` field. An empty result therefore cannot by itself establish a successful zero-valued metric. Pending statuses, missing expected aggregate rows, errors, and timeouts need explicit caveats.
- `get-schema.tables` is a comma-separated list of table names, matched case-insensitively. `search` is a case-insensitive table-name substring. The two filters combine. `includeColumns` defaults to true; table/column limits default to 50 and cap at 200. The result reports tables, `returnedTables`, `totalTables`, and `truncated`, comparing all raw tables with returned filtered tables. This flag can indicate filtering rather than clipping. Column arrays are also subject to the shared 20-element nested-array cap; there is no column cursor or column-name search.
- `list-events` defaults to 25 records, capped at 100. `event`, `after`, and `before` pass to the events endpoint. `propertyKeys` is a comma-separated string. Returns compact events with timestamp, distinct ID, optional person metadata (up to five distinct IDs), selected properties, `count`, and `next`. This is a sample reader, not a population metric.
- `list-persons` defaults to 25 records, capped at 100. `search` passes through to the persons endpoint. It returns identity metadata, up to ten distinct IDs per person, creation time, selected properties, `count`, and `next`. It has no event-time, cohort, or date filters. `maxPropertyValueLength` on event/person tools controls string shortening; without `propertyKeys`, the first 25 properties are returned.
- `list-insights` and `list-feature-flags` use the shared `ProjectResourceSearchInput` type in [posthog-client.ts](../../src/posthog-client.ts). Their limits default to 25 and 50 respectively, each capped at 100. `includeFilters` defaults to false. They return bounded search results, `count`, and `next`; no full query body or dashboard membership is returned by the insight reader.
- `get-insight` takes a string path ID: use the numeric `id` from `list-insights` converted to a string. It returns selected metadata, `lastRefresh`, optional legacy `filters` (default true), and optional stored `result` (default false). It does not return the modern `query` field, force refresh, or accept date overrides. A `shortId` is returned as metadata, but the skill does not assume it is interchangeable with this endpoint's numeric ID.
- `list-feature-flags` returns current ID/key/name, active state, creation time, rollout percentage, optional filters, and creator. It omits update history, exposure events, and experiment definitions/results. `createdAt` is not a rollout-change timestamp.
- Shared `truncateValue` clips nested arrays to 20 entries, objects to 50 entries, and strings to 500 characters by default. It applies recursively to insight results/filters, flag filters, schema columns, properties, and query cells without a separate nested-truncation indicator. Exact reproduction must stop if the necessary definition is absent or shortened.
- There are no registered tools for native trends/funnels/retention, governed-metric catalog operations, insight-query retrieval/refresh, dashboard retrieval, mutations, annotations, logs, traces, or replay. Interactive extension commands are not additional AI tools.
