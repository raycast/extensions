# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

"Toole" (package name `dev-tools`, store title "Dev Tools") is a Raycast extension that bundles a collection of small developer utilities — the kind of one-off tasks developers reach for repeatedly (encoding/decoding, formatting, conversion, generation, etc.). Tools are added one at a time; each tool is a self-contained Raycast command.

## Commands

```bash
npm run dev        # ray develop — hot-reloads the extension into the local Raycast app
npm run build      # ray build — production build / typecheck
npm run lint       # ray lint
npm run fix-lint   # ray lint --fix
npm run publish    # publish to the Raycast Store (not npm)
```

There is no test runner configured. `ray build` is the typecheck/validation gate.

## Architecture: how a tool maps to code

A Raycast command is the unit of a tool, and it lives in two places that must stay in sync:

1. An entry in the `commands` array in `package.json` (the extension manifest).
2. A file `src/<name>.tsx` whose basename **exactly matches** the command's `name`, with a React component as its `default` export.

The manifest entry's `name` is the binding — Raycast looks for `src/<name>.tsx`. For example the manifest command `aes-en--decryptor` resolves to `src/aes-en--decryptor.tsx`. Each command also declares a `mode`: `"view"` renders UI (a `Form`, `List`, `Detail`, etc. from `@raycast/api`), while `"no-view"` runs in the background with no UI.

UI is built from `@raycast/api` primitives (`Form`, `List`, `ActionPanel`, `Action`, `showToast`, …). `@raycast/utils` provides helper hooks. There is no central router or shared app shell — commands are independent entry points. Reusable, UI-free logic (crypto, parsing, conversion) goes in `src/lib/` so it stays out of the command components and can be shared between tools. Shared *React* components (UI reused across commands) live in `src/components/` — `src/lib/` stays UI-free. Raycast only registers top-level `src/<name>.tsx` files whose basename matches a manifest command, so anything under `src/lib/` or `src/components/` is never mistaken for a command.

## Tools

- **AES En-/Decryptor** (`aes-en--decryptor`, `src/aes-en--decryptor.tsx`): a live `Form` where the field you last *edited* (tracked by `lastEdited`) is the source of truth — editing Text (or changing a parameter while in encrypt mode) re-encrypts into `encrypted`; editing Encrypted decrypts back into `text`. `onChange` handlers ignore "echo" events (value unchanged) because Raycast re-fires `onChange` on focus/blur and on programmatic value sets — `textRef`/`encryptedRef` make that comparison race-free. The crypto lives in `src/lib/aes.ts` and supports two **non-interoperable** modes selectable in the form: `ctr` (legacy — 16-byte IV, no tag, payload `[iv | ciphertext]`; byte-compatible with the original tool) and `gcm` (authenticated — 12-byte IV + 16-byte tag, payload `[iv | ciphertext | tag]`, fails loudly on wrong password). The key is derived from the password by chained hashing. File encrypt/decrypt actions write `<file>.aes` / `<file>.decrypted` next to the source. For security the password and derived key are never displayed, copied, or persisted — they exist only in memory while the command is open.

- **Text Encoder/Decoder** (`text-encoder`, `src/text-encoder.tsx`): a live two-way `Form` modeled on the AES tool — the field you last *edited* (`lastEdited`) is the source of truth; editing Text encodes into `encoded`, editing Encoded decodes back into `text`, and `textRef`/`encodedRef` ignore Raycast's focus/blur/programmatic `onChange` echoes. A **Format** dropdown (Base 64, Base 64 URL-safe, Base 32, Hex, URL/percent, Binary) and a **Text Encoding** dropdown (UTF-8 / UTF-16 LE / Latin-1) are parameters that recompute in the active direction. All conversion lives in `src/lib/text-codec.ts`, which routes everything through a `Buffer`: `text --(charset)--> bytes --(format)--> string`. Each format is a `Codec` (`encode`/`decode` over `(text, charset)`); decoders are deliberately lenient (strip whitespace, accept either Base 64 alphabet, accept hex with spaces/colons/`0x`) and throw with a specific message on genuinely malformed input. Base 32 and Binary are hand-rolled (no Node built-in); the rest use `Buffer` encodings. UTF-8 is the only charset whose decode masks differently, so ASCII is intentionally omitted to avoid lossy surprises.
- **Clipboard encode/decode shortcuts** (`base64-encode`, `base64-decode`, `url-encode`, `url-decode`; `src/<name>.ts`): `no-view` commands that delegate to `transformClipboard(format, direction)` in `src/lib/codec-clipboard.ts` — read clipboard → encode/decode (always UTF-8) → write back → `showHUD`. The form command covers the other formats/charsets.
- **Clipboard case shortcuts** (`lowercase`, `uppercase`; `src/<name>.ts`): `no-view` commands that delegate to `transformCase(label, fn)` in `src/lib/case-clipboard.ts` — read clipboard → `toLowerCase`/`toUpperCase` → write back → `showHUD`. Unlike the other clipboard helpers it does **not** trim, so surrounding whitespace/newlines are preserved.
- **JWT Inspector** (`jwt`, `src/jwt.tsx`): a read-only JWT debugger. A `List` with `isShowingDetail`: the left column is one row per claim (Payload then Header sections), the right detail pane shows the selected claim plus the full header/payload as **syntax-highlighted** JSON (Markdown ```json``` fences). The token is *imported*, not edited — prefilled from the clipboard on open if it parses, replaced via a pushed `ImportForm` (`⌘N`) or re-loaded from the clipboard (`⌘⇧V`); an invalid token shows a `List.EmptyView` with the decode error. Each claim row copies its value (Enter), its name (`⌘.`), or — for `exp`/`nbf`/`iat` — its ISO date; global actions on every row copy the whole payload/header/encoded-token/signature and the common registered claims by name (`⌘⇧S`/`I`/`A`/`E`). Decode-only logic lives in `src/lib/jwt.ts` (no crypto, no dependency): `decodeJwt` splits + Base64URL-decodes the segments, and `buildClaims` produces the ordered claim model — registered claims first (canonical RFC 7519 / 7515 order) then custom claims, each with a friendly label, a copy string (raw for strings, JSON otherwise), and a truncated preview. `detectTime` flags any numeric value that looks like a Unix timestamp (the registered `exp`/`nbf`/`iat` are always treated as NumericDate seconds; other integers are matched against a 2001–2100 epoch window in both seconds and milliseconds), producing a `ClaimTime` with the absolute UTC string, ISO date, relative phrase, and — for `exp`/`nbf` — an expired/valid/future state used to tint the row's clock icon. Registered time claims display *relatively*; other detected timestamps display as *absolute UTC*; either way the row subtitle is a `{ value, tooltip }` so the exact epoch number shows on hover (and the raw value is always in the JSON pane). **Signature verification is on-demand only** (never automatic): `Verify Signature` (`⌘⇧Y`) calls `resolveVerificationKey` in `src/lib/jwks.ts`, which finds a public key from the token's own `jwk`/`x5c`/`jku`/`x5u` header or, failing those, OIDC discovery from the `iss` claim (`/.well-known/openid-configuration` → `jwks_uri`, with a `/.well-known/jwks.json` fallback), selecting by `kid`; the actual check (`verifyWithKey` for RS/PS/ES, `verifyWithSecret` for HS) lives in `jwt.ts` and operates on the stored `signingInput`. `Verify with Key or Secret…` (`⌘⇧K`) pushes a form to supply an HMAC secret or a PEM key manually. The result is shown via toast and the detail's signature footer. `jwks.ts` is the **only** place that touches the network, and only when the user triggers verification — there is no signing.
- **Number Base Converter** (`number-base-converter`, `src/number-base-converter.tsx`): a `List` whose search bar *is* the number input; it shows decimal/hex/octal/binary plus a Unicode code-point preview live, each row copyable, and prefills from the clipboard. Source base is `auto` (a `0x`/`0b`/`0o` prefix wins; otherwise any a–f digit implies hex, else decimal) or forced via the search-bar dropdown.
- **Clipboard conversion shortcuts** (`decimal-to-hex`, `hex-to-decimal`, `decimal-to-binary`, `binary-to-decimal`; `src/<name>.ts`): `no-view` commands that each delegate to `convertClipboard(from, to)` in `src/lib/convert-clipboard.ts` — read clipboard → convert → write back → `showHUD`. No UI.
- **Text Analyzer** (`text-analyzer`, `src/text-analyzer.tsx`): a hybrid view. The root `Form` has a multiline `TextArea` prefilled from the clipboard on open, with a live headline `Form.Description` (characters/words/lines/size/reading time) recomputed from the cheap `quickSummary()` on each keystroke. A **Show All Metrics** action pushes a `List` that runs the full `analyze()` and shows every metric as a copyable row grouped into sections (Counts, Size & Encoding, Readability & Timing, Character Classes); each row's `ActionPanel` also carries Copy Full Report / Copy as JSON. A **Character distribution** row pushes a third `List` (`characterFrequency()`) of per-code-point counts and percentages, sorted descending, searchable. All metric logic is pure and lives in `src/lib/text-analysis.ts`.

Number logic lives in `src/lib/number-base.ts` and uses `BigInt`, so arbitrarily large integers convert exactly (`Number` would lose precision past 2^53). Text-analysis logic lives in `src/lib/text-analysis.ts`: it counts Unicode code points (`[...text]`), UTF-16 units (`string.length`), grapheme clusters (`Intl.Segmenter`, with a code-point fallback), and UTF-8 bytes (`Buffer.byteLength`), and uses Unicode property escapes (`/\p{L}/gu`, etc.) for character classes.

- **Color Converter** (`color-converter`, `src/color-converter.tsx`): one `List` command with two modes via the view dropdown (`view` state = `"overview" | ColorModel`). Input accepts hex/`rgb()`/`hsl()`/`hsv()`/`hsb()`/`hwb()`/`oklch()` and **CSS names** (`src/lib/css-colors.ts`; `parseColor` resolves names first, `colorName` reverse-looks-up).
  - **Overview** (default, no detail pane — deliberately, to avoid image-reload flicker): `Overview` component renders Formats (incl. the CSS name when matched), Shades & Tints (`shades()`), and Harmonies (`harmonies()`) as rows with swatch icons + copy/use-as-base actions. ⌘E jumps to editing.
  - **Editor** (a model is selected): `EditorView` shows one row per channel and a single shared `renderColorPanel()` SVG in the detail pane. The panel image is **independent of selection** (no per-row focus highlight) so navigating rows doesn't reload it — only a value change does; this is the flicker fix. Channels adjust with ⌘←/→, ⌘⇧←/→ (×5); ⌘O returns to Overview.

  Raycast has **no slider/pointer/color-wheel component**, so sliders are SVG visuals driven by keyboard, not mouse-draggable. The model abstraction in `src/lib/color.ts`: `COLOR_MODELS`, `channelsOf`, `withChannel`, `modelString`, `channelGradientHexes`, plus `rgbToHwb`/`hwbToRgb` and `rgbToOklch`/`oklchToRgb` (OKLab matrices). Canonical form is RGBA (r/g/b 0–255, a 0–1). `formatColor`/`detectFormat`/`adjustHsl` remain in the lib but are unused by the view.

- **Unix Timestamp** (`unix-timestamp`, `src/unix-timestamp.tsx`): a `List` whose search bar *is* the input (same pattern as Number Base Converter / Cron Expression). A **numeric** input is read as a Unix timestamp; a **non-numeric** input is parsed as a date string (`Date.parse`), giving the reverse direction. The unit is auto-detected from the integer's significant-digit count (≤11 → seconds, ≤14 → ms, ≤17 → µs, else ns — biased so modern values land in a plausible date range) or forced via the search-bar dropdown (Auto / Seconds / Milliseconds / Microseconds / Nanoseconds). It shows Local, UTC, ISO 8601, RFC 2822, and relative time, plus the instant in every unit (the one matching the input is tagged). With the field empty it shows the live current epoch (a 1 s `setInterval` ticks `now`) and example inputs; prefills from the clipboard. All logic is pure and lives in `src/lib/unix-time.ts`: the canonical representation is **`BigInt` nanoseconds**, so µs/ns timestamps convert exactly (`Number` loses precision past 2^53); the `Date` (ms precision) is derived from it for the human formats. Fractional timestamps and date strings round through `Number`. `detectUnit`, `parseInput`, `toUnits`, `formats`, and `relative` are the entry points.

- **Cron Expression** (`cron-expression`, `src/cron-expression.tsx`): a `List` whose search bar *is* the cron input (same pattern as Number Base Converter); prefills from the clipboard when it parses. It shows a plain-English summary, a per-field breakdown, and the next N run times (5/10/25, chosen via the search-bar dropdown) with relative-time accessories — each row copyable. All logic lives in `src/lib/cron.ts`: `parseCron` (5-field, or 6-field with a leading seconds field; `@yearly`/`@monthly`/`@weekly`/`@daily`/`@hourly` and friends; month/weekday names; `*` `,` `-` `/` `?` operators, including wrap-around ranges like `fri-mon`), `describe`/`describeFields` (human text), and `nextRun`/`nextRuns` (computed by stepping local `Date` fields, ~6-year horizon). Day-of-week is `0–6` with `0`/`7` = Sunday; when **both** day-of-month and day-of-week are restricted, a day matches if **either** does (the Vixie-cron OR rule — `dayFieldsAreOr` surfaces a UI note). Quartz-only tokens (`L`, `W`, `#`) and the trailing year field are intentionally unsupported and raise a clear parse error.

- **JSON Converter** (`json-converter`, `src/json-converter.tsx`): a live `Form` that converts structured data between formats via a **hub-and-spoke** model — every format `parse`s to a plain JS value and `stringify`s back from one, so conversion is always `stringifyValue(parseInput(input, from), to, options)`. The `From` dropdown is `auto` (uses `detectFormat`, shown in the field's `info`) or an explicit override; `Swap` feeds the output back as input with From/To traded. Output is a read-only `Form.TextArea`; parse/convert errors surface on its `error` (same pattern as the AES tool's `decryptError`). The engine is `src/lib/formats.ts` (`Format` union, `FORMATS`/`LABEL`, `parseInput`/`stringifyValue`/`convert`/`detectFormat`, `ConvertOptions`). Supported formats and their backings: JSON (native), JSON5 (`json5`), YAML (`yaml`), TOML (`smol-toml`), JS/TS object (`src/lib/js-object.ts`), XML (`fast-xml-parser`), CSV/TSV (`papaparse`), `.env` and query string (hand-rolled in `formats.ts`).
  - **JS is evaluated, not just parsed.** `evalJs` in `src/lib/js-object.ts` runs a pasted snippet through `node:vm` (`runInNewContext`, 1s timeout, no `require`/`process`/network), handling bare expressions, `export default …`, `module.exports = …`/`exports.x = …`, and single `const/let/var name = …` declarations. `detectFormat` itself never evaluates (it leans on syntax), but `auto`-detecting `js` and then converting does run the snippet — this is intended (the user opted into evaluation). `stringifyJs` renders a value back to JS source with options: `quotes` (double/single), `quoteKeys` (as-needed/always), `indent`, `declaration` (none/`const`/`let`/`export-default`/`module-exports`), `semi`, `trailingComma`, `asConst`; it also renders `BigInt` as `10n` and `Date` as `new Date("…")`.
  - **Lossy/flat formats** (documented intent, not bugs): TOML/`.env`/query/CSV have no `null`, so those keys drop on the way out; `.env` flattens nested objects with `_`-joined keys and JSON-encodes arrays; query strings and CSV are flat/tabular; XML is order- and attribute-lossy. `ConvertOptions.indent` (`2`/`4`/`tab`/`minified`) and `sortKeys` apply across structured formats; `JSON`/`JSON5` use a replacer so `BigInt` serializes (as a decimal string) instead of throwing.
- **JSON clipboard shortcuts** (`format-json`, `minify-json`, `json-to-yaml`, `yaml-to-json`, `json-to-js`; `src/<name>.ts`): `no-view` commands that each delegate to `transformClipboard(label, transform)` in `src/lib/format-clipboard.ts` (the parallel of `convert-clipboard.ts`) — read clipboard → run a `convert(...)` text transform → write back → `showHUD`. No UI.
- **Unicode Browser** (`unicode-browser`, `src/unicode-browser.tsx`): a **grid-first** `Grid` (8 columns — Raycast's max) whose cells are characters (glyph + 4-hex code point). The `searchBarAccessory` is a `Grid.Dropdown` of every block grouped into `Grid.Dropdown.Section`s by plane (the "categories"); selecting one browses that block. Typing controls the view via `onSearchTextChange` (`filtering={false}`): `search()` resolves a code-point query (`U+…`/`0x…`/`\u…` or bare 4–6 hex) or a pasted single character directly, otherwise substring-scans names, and also returns matching blocks — rendered as a "Blocks" section above a "Characters" section. Selecting a cell pushes `CharDetail` (a `Detail` with a large glyph via `glyphImage`, name heading, and a `Detail.Metadata` panel). Every character shares `CharActions` (Copy Character / Code Point ⌘⇧C / Name / HTML Entity / JS Escape, Paste ⌘V, Show Details ⌘I); controls/unassigned omit the character copy/paste. Both browse and search are paginated (`pageSize` 200) so huge CJK blocks never fully materialize (`charsInBlock` is pure arithmetic).
  - Logic is in `src/lib/unicode.ts` (pure): `BLOCKS`/`RANGES`/`PLANES` from the eager small JSON; `nameOf` (named lookup → algorithmic synthesis for CJK/Tangut/**Hangul** (jamo decomposition)/surrogate/private-use ranges → control fallback), `blockOf`/`planeOf` (binary search), `gcOf`, `gcGroup`/`GC_NAME`, `search`, `charInfo` (full metadata: UTF-8/UTF-16, escapes, age), and `copyFields` (Buffer-free per-cell copy strings). Glyph rendering is in `src/lib/unicode-glyph.ts`: `glyphIcon`/`glyphImage` build theme-aware (`environment.appearance`) data-URI SVGs — a centered glyph for printable code points, a dashed **abbreviation box** (`CONTROL_ABBR`: NUL…APC, DEL) for controls/format/surrogate/unassigned; icons are cached by `cp:appearance`.
  - **Data is generated, not hand-written.** `scripts/generate-unicode-data.mjs` (standalone Node ESM, run manually on a Unicode version bump — **not** part of `ray build`, ships no runtime dep) downloads `UnicodeData.txt`/`Blocks.txt`/`DerivedAge.txt` from `unicode.org` (pinned `16.0.0`) and writes `src/lib/data/unicode-blocks.json` (small, ~338 blocks + 19 First/Last algorithmic ranges + version — imported eagerly) and `assets/unicode-names.json` (~40k named code points `[cp,name,gc,age]` — read once lazily via `fs` from `environment.assetsPath`, kept out of the JS bundle and TS type graph). CJK/Hangul/etc. are stored as ranges and named at runtime, so the names file stays ~40k rows, not ~150k.
- **Code Formatters & Minifiers** (per-language commands; 10 `format-<lang>` + 6 `minify-<lang>`, `src/<name>.tsx`): each command is a ~5-line wrapper that imports **only its own** language impl and renders `FormatView`/`MinifyView` (`src/components/format-view.tsx` / `minify-view.tsx`) with that impl passed as the `run` prop. **Format** covers JavaScript, TypeScript, CSS, SCSS, Less, HTML, XML, SQL, Markdown, YAML; **Minify** covers JavaScript, TypeScript, CSS, HTML, XML, SQL (SCSS/Less/Markdown/YAML have no minifier — `canMinify` in `src/lib/languages.ts`). The views wrap the shared `CodeToolView` (`src/components/code-tool-view.tsx`), which holds all the UI: it prefills from the clipboard, recomputes live, and renders per-language settings driven by `FORMAT_FIELDS`/`MINIFY_FIELDS` (`src/lib/format-options.ts` / `minify-options.ts`) via a flat `FIELD_SPECS` map of dropdowns/checkboxes. `CodeToolView` imports **no** formatter/minifier libraries — the work is injected as a `transform` function.
  - **Bundle isolation (this is load-bearing, not just tidiness):** Raycast builds one self-contained bundle **per command** with no code-splitting, so anything statically reachable from a command's entry is bundled into it. The work therefore lives in **per-language modules** under `src/lib/format/<lang>.ts` and `src/lib/minify/<lang>.ts`, each importing only the parser/minifier it needs; a command imports just its own. This keeps each command ~0.02–1.6 MB instead of ~40 MB. **Do not** reintroduce a central `format.ts`/`minify.ts` that imports every language — that put the full library set (most fatally the ~10 MB `typescript` compiler) into all 16 commands and made them fail to load with "Connection interrupted". For the same reason, `code-tool-view.tsx` must not statically import any language impl.
  - **Async recompute (differs from the text-encoder pattern):** formatting/minifying is `async`, so the live loop is **not** the synchronous AES/text-encoder one. A monotonic `seqRef` request id guards every result (a slow run for stale input is dropped), keystrokes are debounced ~250 ms, the input `onChange` ignores Raycast's echoes via `inputRef`, and a parse error keeps the last good output while showing the cleaned first-line message inline.
  - **First use of `LocalStorage`:** settings persist **per command** via `src/lib/settings-store.ts` (key `settings:<operation>:<language>`), loaded on mount (merged over defaults so new options are forward-compatible) and saved on every change. No other tool persists anything.
  - **Formatting** (`src/lib/format/`): prettier via **`prettier/standalone` + explicitly-imported plugin objects** (no runtime filesystem plugin resolution — required in a bundled extension); `prettier-common.ts` holds the shared driver (imports the prettier core only), and each language module adds its own plugins (`@prettier/plugin-xml` for XML; `sql-formatter`, its own dialect/keyword-case engine, for SQL — no prettier). **Minification** (`src/lib/minify/`): `terser` for JS (mangle/compress/drop-console/-debugger, shared `terser-common.ts`), TypeScript type-stripped first with **`sucrase`** (a ~0.7 MB pure-JS TS→JS transpiler — chosen over the full `typescript` compiler for bundle size and over esbuild, which needs a native binary), `clean-css` for CSS, `html-minifier-terser` for HTML (minifies inline JS/CSS too), and hand-rolled `src/lib/xml-minify.ts` / `src/lib/sql-minify.ts`. The hand-rolled minifiers are string/CDATA-aware (SQL preserves literals containing `--`; XML preserves text nodes/CDATA) but have documented caveats (no `xml:space="preserve"`, no SQL dollar-quoting).

## Adding a new tool (do all of these together)

When you implement a new tool, keep the manifest, source, and docs in lockstep:

1. Add a command object to `commands` in `package.json` (`name`, `title`, `description`, `mode`).
2. Create `src/<name>.tsx` (basename === `name`) exporting a default component for `view` commands, or `src/<name>.ts` exporting a default async function for `no-view` commands.
3. Add a dated entry under `CHANGELOG.md`.
4. **Update this CLAUDE.md.** Per the project owner's intent, this file is the living documentation of the extension and must be kept current as features land. Once tools are real (not stubs), maintain a short list of the tools and what each does, so future instances don't have to reverse-engineer the manifest.

## Conventions

- TypeScript with `strict: true`; JSX via `react-jsx` (no `import React` needed).
- Prettier: `printWidth` 120, double quotes (`singleQuote: false`). Run `fix-lint` before considering a change done.
- ESLint extends `@raycast/eslint-config`.
- Not currently a git repository.
