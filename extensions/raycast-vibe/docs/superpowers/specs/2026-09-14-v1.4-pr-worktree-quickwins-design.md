# Vibe v1.4 — PR + Worktree Bridge + Quick Wins

Three small features that leverage v1.1 (headless agents), v1.2 (worktrees), and v1.3 (GitHub) simultaneously:

- **F1. Check out PR as worktree** — combines v1.2 + v1.3.
- **F2. AI PR description** — reuses v1.1's headless pattern for a PR body draft.
- **F3. Open Last Project** — a root-level Raycast no-view command.

## Goals

- Bridge the v1.2 and v1.3 subsystems with the workflow AI-agent users already do manually (spawn a worktree for a PR under review).
- Extend the AI-commit pattern to PR bodies so the "review this PR" and "draft this PR" flows both get one-keystroke AI help.
- Bypass the search step for the 80% flow (`open the project I just used`).

## Non-goals

- PR comments / approvals / merges in Vibe (deferred to v1.6).
- Non-GitHub forges.
- Custom naming templates for the PR worktree directory.
- Branching AI-PR-description mode by base branch (default branch is the base — no override).

## Dependencies

v1.4 structurally depends on:
- v1.1 — headless agent runner, `pickHeadlessAgent`.
- v1.2 — worktree helpers (`addWorktree`, `worktreeDir`, `sanitizeBranchName`, `directoryExists`, `removeWorktree`).
- v1.3 — GitHub dashboard view and `gh` availability check.

The v1.4 branch is stacked on `test/all-features` (which already contains all three merges) so the tree compiles as-is. The v1.4 PR against `main` will display v1.1+v1.2+v1.3+v1.4 diffs until the earlier PRs merge; when they land, GitHub auto-narrows the PR to just v1.4's diff.

## Features

### F1. Check out PR as worktree

**UX**

- New action on each `PullRequestItem` in `src/views/GitHubDashboard.tsx`: **Check Out as Worktree**. Present on both the "Open Pull Requests" and "Reviews Requested" sections.
- Placement: after **Copy Branch Name**, before **Refresh**.

**Behaviour**

1. Compute target directory: `worktreeDir(repoRoot, `pr-${pr.number}-${sanitizeBranchName(pr.headRefName)}`)`.
2. Refuse (toast) if the directory already exists.
3. `gh availability` check (missing / unauthenticated toasts, same as v1.3 friendly messages).
4. Run `gh -C <repoRoot> pr checkout <pr.number> --branch pr-<n> --force`:
   - `--branch pr-<n>` gives us a deterministic local branch name (avoids collisions when the PR's headRef already exists locally, e.g., our own PRs).
   - `--force` here reassigns the ref we chose (safe: we named it ourselves).
5. Run `git -C <repoRoot> worktree add <targetDir> pr-<n>` to attach the local branch to the new worktree.
6. On any step's failure: surface stderr in a toast, and if the worktree partially created, remove it via `removeWorktree(repoRoot, targetDir)`.
7. On success: toast "Checked out PR #<n>" then push `AgentPicker` bound to the new worktree so the user can immediately launch Claude/Codex to review the PR.

**Notes on `gh pr checkout` behaviour**

- For same-repo PRs, `gh pr checkout` normally checks the branch out in the current tree. We prevent this by naming the branch (`--branch pr-<n>`) and NOT allowing gh to move HEAD in the main tree: the two-step sequence creates the branch in the main index but leaves HEAD alone, and then `git worktree add` attaches it to the new directory.
- For cross-repo (fork) PRs, `gh pr checkout` sets up a detached tracking configuration; the `--branch` flag still gives us a local name we can `git worktree add` from.
- If `gh pr checkout` moved the main tree's HEAD despite our args, that's a bug in this flow — we detect it by checking `git symbolic-ref HEAD` before and after, and if HEAD moved, we restore it via `git switch -` before the toast fires. See Error Handling.

### F2. AI PR description

**UX**

- New action in `FolderActions` (in `src/vibe.tsx`): **AI Pull Request Description**.
- Visibility: same gate as v1.3's Create Pull Request (`folder.repositoryRoot && githubRemote`) AND at least one headless-capable agent enabled (same rule as v1.1's Ask/Commit).

**Behaviour**

1. Resolve default branch via `gh -C <repoRoot> repo view --json defaultBranchRef -q '.defaultBranchRef.name'`. Fall back to `main` if `gh` returns nothing.
2. Resolve current branch via `git symbolic-ref --short HEAD`.
3. If current == default: toast "You're on the default branch. Switch to a feature branch first." Abort.
4. Read commits: `git log <default>..HEAD --format="%h %s%n%b%n---"` (with a `---` separator so parsing is trivial).
5. If empty output: toast "No commits ahead of default branch." Abort.
6. Truncate at 50 KB (same rule as F4/aiCommit).
7. Run headless agent (same selection as v1.1 F3/F4) with this prompt:

```
Compose a pull request title and body from the following commits.

Rules:
- Title: imperative mood, under 72 chars, no trailing period.
- Body: two sections. "## What" — bullet list of user-visible changes. "## Why" — one short paragraph on motivation.
- Do not include the commit shas or the commit messages verbatim.
- Output EXACTLY this format, no fences or preamble:

TITLE
---
BODY

Commits:
<COMMITS>
```

8. Parse response by splitting on the first `\n---\n` (or `\n---\n`) into `title` and `body`. If the separator is missing, treat the whole response as `body` and set `title` to the first line of `body`.
9. Copy the body to the clipboard.
10. Success toast: title = "PR body copied", message = the generated title (visible to user for reference).
11. User pastes the body into `gh pr create --web`'s draft or GitHub's UI.

### F3. Open Last Project

**UX**

- A second Raycast command registered in `package.json` under `commands`: name = `open-last-project`, title = `Open Last Project`, mode = `no-view`, subtitle = `Vibe`.

**Behaviour**

1. Load recent-folders list via `getPaths(RECENT_FOLDERS_KEY, 1)`; take the first entry.
2. If nothing: `showHUD("No recent Vibe project.")` and exit.
3. Load last-agent map; look up the agent id for that folder path.
4. If agent id and agent still enabled → `launchAgent(folder, agent)`.
5. Else → find the `terminal` pseudo-agent and launch it (opens a plain shell in the folder).
6. `closeMainWindow()` before/after Toast to give the no-view command its "just do it" feel.

## Module layout

- `src/prCheckout.ts` — new module for F1. Exports `checkoutPullRequestAsWorktree(repoRoot: string, pr: { number: number; headRefName: string }): Promise<{ worktreePath: string }>`. Rejects on any failure. Wraps the two-step gh + git flow and the partial-state cleanup.
- `src/aiPRDescription.ts` — new module for F2. Exports `runAIPRDescription(folder: { repositoryRoot: string; ... }, agent: Agent): Promise<void>`. Mirrors `src/aiCommit.ts` shape.
- `src/openLastProject.tsx` — new Raycast command entry file for F3. Default export is the command (no-view, no React render — just an async function returning `undefined`).
- `src/views/GitHubDashboard.tsx` — extend `PullRequestItem` with the F1 action. Requires the parent view to know `repoRoot` (already has it) and to receive a callback to refresh + push AgentPicker on success.
- `src/vibe.tsx` — wire F2 action in `FolderActions`; export a few more helpers if F3 needs them (already-exported `launchAgent`, `agents`, `getPaths`, `RECENT_FOLDERS_KEY` — the last one may need exporting).
- `package.json` — add second `commands` entry for `open-last-project`.

## Data & type changes

None. F1 and F2 add no persisted state. F3 reads existing `RECENT_FOLDERS_KEY` and `LAST_AGENTS_KEY` LocalStorage.

## Error handling

| Case | Behaviour |
|------|-----------|
| F1 target dir exists | Toast "Worktree already exists at `<path>`". Abort. |
| F1 gh missing / unauthenticated | Same friendly toasts as v1.3. |
| F1 `gh pr checkout` fails | Toast with stderr. If the branch was created but worktree add failed, `git branch -D pr-<n>` cleanup (only branch we created, only if we created it, only if unused). |
| F1 `git worktree add` fails | Toast with stderr. Attempt cleanup: remove the (empty) target dir if present. |
| F1 HEAD moved unexpectedly | Detected via before/after `git symbolic-ref HEAD`; restore with `git switch -`, toast that a restore happened. |
| F2 no headless agent | Action hidden. |
| F2 on default branch | Actionable toast, abort. |
| F2 no commits vs default | Actionable toast, abort. |
| F2 agent failure | Same handling as v1.1's aiCommit. |
| F3 no recent project | `showHUD("No recent Vibe project.")`. |
| F3 last-agent id no longer enabled | Fall back to terminal-in-folder. |
| F3 recent folder path no longer exists on disk | `showHUD("Last Vibe project no longer exists on disk.")`. |

## Storage

None new. F1 and F2 stateless. F3 reads existing keys only.

## Testing

Same posture. `npm run lint && npm run build`. Manual smoke:

1. **F1 happy path** — on a public repo PR, action → worktree created, AgentPicker pushed. Directory exists on disk.
2. **F1 duplicate** — invoke twice — second time surfaces "worktree already exists".
3. **F1 fork PR** — action on a PR from a fork; worktree contains the fork's ref.
4. **F1 cleanup on failure** — with gh temporarily unauthenticated (revoke token), action fails and no partial state remains.
5. **F2 happy** — on a feature branch with 3 commits, generated title + body copied. Paste into gh pr create --web draft.
6. **F2 default branch** — on `main`, action shows the "switch to a feature branch" toast.
7. **F2 no commits ahead** — on a feature branch with the same HEAD as default, toast fires.
8. **F3 happy** — trigger "Open Last Project" from Raycast root → terminal opens in the most-recent project's path, running the last-used agent if any.
9. **F3 no recent** — clear LocalStorage recent list, trigger — HUD "No recent Vibe project."
10. **F3 stale path** — recent project on disk deleted, trigger — HUD "Last Vibe project no longer exists on disk."
