# Vibe v1.2 — Git Worktrees

Adds worktree management to Vibe (list, create, remove) plus a one-step "Launch Agent in New Worktree" flow. Worktrees live at `<repoRoot>/.worktrees/<branch>` and follow Vibe's safety posture: a single destructive operation (worktree removal) gated by dirty-check + explicit confirm, no `--force`, no branch deletion.

## Goals

- Let power users spin off isolated worktrees for parallel agent runs from one keystroke.
- Reuse the v1.1 agent launch surface without modification — a worktree is just a folder path.
- Keep the branch-safety posture unchanged: no branch deletion, no forced removal, no destructive `git worktree` flags.

## Non-goals

- Removing branches after worktree removal.
- `git worktree prune` / stale registration cleanup UI. (Manual for now.)
- Copying uncommitted changes across worktrees.
- User-configurable worktree base path.
- Making worktrees appear in the main Vibe project search (they are launched from the Worktrees list, not browsed).

## Features

### W1. List worktrees

New action in `FolderActions`: **Worktrees** (visible only when `folder.repositoryRoot` is set). Pushes `WorktreeList`.

`WorktreeList` calls `git worktree list --porcelain` and renders one `List.Item` per entry:

- **Main working tree** first, marked with icon `Icon.House` and subtitle "main working tree". Actions: Choose Agent, Open in Terminal, Open in VS Code / Cursor / Finder, Copy Path. **No Remove.**
- Each `.worktrees/*` entry with:
  - Title = last path segment.
  - Subtitle = full path.
  - Accessories: branch name (or "detached"), short SHA, `dirty` marker if `git status --porcelain` in that worktree is non-empty.
  - Actions: Choose Agent, Open in Terminal, Open in VS Code / Cursor / Finder, Copy Path, **Remove Worktree** (W3).

Root `ActionPanel` on `WorktreeList`:
- **New Worktree from Current Branch** — pushes `NewWorktreeForm` (W2a).
- **Check Out Branch as Worktree** — pushes `WorktreeBranchPicker` (W2b).

Dirty status is computed per-worktree on load via `Promise.all` over `git -C <worktree> status --porcelain --untracked-files=no` (typical repos have well under 20 worktrees; no need for a concurrency cap). Failed status checks render the item without the dirty marker rather than erroring the whole list.

### W2a. New worktree from current HEAD

`NewWorktreeForm` — one `TextField` (branch name, required).

Validation on submit:
1. Trim; reject empty.
2. Reject if `git check-ref-format --branch <name>` exits non-zero.
3. Reject if the branch already exists locally OR the target directory exists.

Path composition:
- Directory basename = `sanitizeBranchName(branch)` — replace any `/` in the branch name with `-` (for `feature/foo` → `feature-foo`). Slashes are legal in branch names but not desirable as nested directories inside `.worktrees/`.
- Full path = `<repoRoot>/.worktrees/<basename>`.

Execution:
- `git -C <repoRoot> worktree add <path> -b <branch>`.
- On success: toast "Worktree created", pop back to `WorktreeList` which refreshes.
- On failure: error toast with `gitErrorMessage(err, "Could not create worktree")`.

### W2b. Check out existing branch as worktree

`WorktreeBranchPicker` — a `List` with two sections `Local Branches` and `Remote Branches` (same shape as the existing `BranchPicker` in `vibe.tsx`). Branches with active worktrees or that match the current HEAD are shown but their action is disabled with a subtitle "already checked out here" (git will refuse anyway; failing fast in the UI is friendlier).

Local branch selected → `git worktree add <.worktrees/basename> <branch>`.

Remote branch selected → `confirmAlert` "Create local branch `<name>` tracking `<remote>` and check it out as a worktree?" → on confirm: `git worktree add <.worktrees/basename> -b <name> <remote>`.

Basename sanitization identical to W2a.

### W3. Remove worktree — DESTRUCTIVE

Two gates:

1. **Dirty check.** `git -C <worktree> status --porcelain` (all files, including untracked). If non-empty:
   - Toast (Failure) with title "Worktree has uncommitted changes" and message "Commit or discard them in the worktree first." Abort. **No `--force`.**

2. **Explicit confirm.** `confirmAlert` with `Alert.ActionStyle.Destructive`:
   - Title: "Remove worktree?"
   - Message: `<worktree path>\n\nThe branch '<branch>' will be preserved.`
   - Primary action: "Remove"

On confirm: `git -C <repoRoot> worktree remove <worktree>`. `git worktree remove` refuses on dirty trees itself — a defense in depth, still no `--force`.

On success: toast "Worktree removed", refresh list.
On failure: error toast with git stderr surfaced.

The branch is never deleted by this flow.

### W4. Launch Agent in New Worktree

The killer feature — new action in `FolderActions`: **Launch Agent in New Worktree** (visible when `folder.repositoryRoot` is set).

Pushes a form with two fields:
- Branch name (`TextField`, required, same validation as W2a).
- Agent (`Dropdown`, populated from `agents()` filtered to non-`terminal` agents, required).

Submit:
1. Run the W2a creation path with the given branch name.
2. On success, immediately call `launchAgent(worktreePath, agent)` — reuses all v1.1 wiring (env, terminal, remembering).
3. Pop back to the calling view.

On any step failing, abort with the corresponding error toast; do not partially launch.

## Data & type changes

New types in `src/worktrees.ts`:

```ts
export type Worktree = {
  path: string;
  branch?: string;   // undefined if detached
  sha: string;       // short SHA (7 chars)
  isMain: boolean;
  detached: boolean;
  dirty?: boolean;   // undefined if status check failed
};
```

No changes to existing types.

## Module layout

- `src/worktrees.ts` — pure helpers, one clear responsibility (git worktree operations + parsing):
  - `listWorktrees(repoRoot: string): Promise<Worktree[]>` — parses `git worktree list --porcelain`.
  - `enrichDirty(worktrees: Worktree[]): Promise<Worktree[]>` — adds `dirty` per entry via bounded parallel status checks.
  - `addWorktree(repoRoot: string, args: { branch: string; base?: string; useExistingBranch?: boolean }): Promise<string>` — returns the created path.
  - `removeWorktree(repoRoot: string, worktreePath: string): Promise<void>`.
  - `sanitizeBranchName(branch: string): string` — `/` → `-`.
  - `worktreeDir(repoRoot: string, branch: string): string`.
  - `validateBranchName(branch: string): Promise<{ ok: true } | { ok: false; reason: string }>` — wraps `git check-ref-format`.
- `src/views/WorktreeList.tsx` — the list view (W1). Depends on `worktrees.ts`, `AgentPicker` (existing), the open-in-editor actions (existing).
- `src/views/NewWorktreeForm.tsx` — W2a form. Also used by W4 with an `agent?: Agent` prop; when set, the form auto-launches after create.
- `src/views/WorktreeBranchPicker.tsx` — W2b branch picker. Reuses `listBranches` from `vibe.tsx` (already exported? if not, export it — same pattern as Task 5 of v1.1).
- `src/vibe.tsx` — wire two new actions in `FolderActions`: **Worktrees** (pushes `WorktreeList`) and **Launch Agent in New Worktree** (pushes `NewWorktreeForm` with an `agent` field enabled).

Existing helpers that new views need — `listBranches`, `runGit`, `confirmGitChange`, `gitErrorMessage` — will be exported from `vibe.tsx` as needed. The circular-import pattern established in v1.1 (`views/*` importing from `../vibe`) holds; all reused helpers are top-level function declarations (hoisted), so no runtime issue.

## Error handling

| Case | Behaviour |
|------|-----------|
| Invalid branch name | Form validation error before submit. |
| Branch already exists locally (W2a) | Toast: "Branch '<name>' already exists". No git call. |
| Target directory exists | Toast: "Worktree directory already exists at <path>". No git call. |
| `git worktree add` fails | Surface stderr via `gitErrorMessage`. |
| `git worktree remove` refuses | Surface stderr; never retry with `--force`. |
| Worktree dirty on remove | Refuse in Vibe layer with actionable message; git would also refuse. |
| Status check per-item fails | Item renders without dirty marker (do not fail the list). |
| Not a git repo | Actions hidden (`folder.repositoryRoot` gate). |
| Race: worktree deleted between list and action | Refresh list on next action; toast the git error. |

## Storage

None. Git is the source of truth. No new LocalStorage keys.

## Testing

Same posture as v1.1: no test suite. Verification per task = `npm run lint && npm run build`. Manual smoke checklist:

1. **W1 list** — from a repo with no worktrees, open Worktrees; only the main working tree shows.
2. **W2a create** — create `test-branch`; list refreshes with the new entry; directory exists at `.worktrees/test-branch`.
3. **W2a invalid name** — attempt `feature//bad`; form rejects.
4. **W2a duplicate** — attempt an existing branch; error toast.
5. **W2b checkout local** — pick a local branch; worktree created.
6. **W2b checkout remote** — pick a remote branch; confirm dialog; local branch created + worktree.
7. **W3 dirty refuse** — modify a file in the worktree; Remove refuses with actionable toast.
8. **W3 clean remove** — clean the worktree; confirm dialog; directory deleted; branch preserved.
9. **W4 launch in new worktree** — Branch = `agent-scratch`, Agent = Claude Code; worktree created + Claude opens in Terminal at the new path.
10. **W4 agent failure** — with Claude command misconfigured, submit W4; worktree gets created, but agent launch surfaces the existing failure toast (partial state is OK — the branch/worktree persists so the user can retry manually).
