# Vibe v1.1 — Agent Workflows

Four agent-native features that extend Vibe's existing "launch an agent in a project" flow with prompt templates, session resume, one-shot Q&A, and AI commit messages.

## Goals

- Give power users faster paths from "I have a repo selected" to "an agent is doing what I want", without leaving Raycast.
- Reuse the existing terminal launch, `LocalStorage`, and Git plumbing. No new external dependencies.
- Preserve Vibe's safety posture: no automatic writes to the repo, no destructive Git commands.

## Non-goals

- Headless invocation for user-configured custom agents (deferred).
- Persisted Q&A history for the "Ask about this repo" feature.
- Any UI in Vibe that stages, amends, or creates commits. F4 outputs to the clipboard only.
- Streaming of headless agent responses. Responses are shown after the CLI exits.

## Features

### F1. Prompt-on-launch templates

**UX**

- `AgentPicker` (existing) gets a second action per agent: `Launch <Agent> with Prompt…` (secondary). Primary remains `Launch <Agent>`.
- The secondary action pushes a `TemplateList` view.
- `TemplateList` shows built-in templates plus user-created ones. Root `ActionPanel` action: `New Template`. Per-template actions:
  - `Launch <Agent> with Template` (primary)
  - `Edit Template` (custom only; hidden for built-ins)
  - `Delete Template` (custom only; hidden for built-ins)
- `New Template` / `Edit Template` push a `Form` with two fields: `Title` (text field, required), `Prompt` (text area, required).

**Built-in templates (merged in at read time, not persisted)**

- `builtin:summarize-repo` — "Summarize this repository. Cover: purpose, primary language/framework, entry points, and how to run it locally."
- `builtin:explain-last-commit` — "Explain the most recent commit on the current branch. Cover: what changed, why (based on message and diff), and any risks."
- `builtin:review-uncommitted` — "Review my uncommitted changes. Flag bugs, missing tests, and anything that shouldn't be committed."
- `builtin:fix-failing-tests` — "Run the test suite for this repo, identify failing tests, and propose fixes."

**Applying a template**

The chosen template's prompt is shell-quoted and appended to the agent's args before launch:

```
<agent.command> <agent.args> "<template.prompt>"
```

All three built-in agents accept a trailing positional prompt when launched interactively. Custom agents that don't support this pattern will misbehave; that is documented and considered user responsibility.

**Storage**

- Key: `vibe-prompt-templates`
- Value: `PromptTemplate[]` — user-created only. Built-ins are constants in code.
- Type: `{ id: string; title: string; prompt: string }`. Custom IDs are prefixed `custom:` and generated with `crypto.randomUUID()`.

### F2. Resume last agent session

**UX**

- `FolderActions` gets a `Resume Last Agent` action.
- Visibility rule: shown only when
  1. A last-used agent is recorded for this folder (existing `LAST_AGENTS_KEY`), and
  2. That agent's id is in the resume-capable set (`claude`, `codex`).
- No new preferences.

**Resume args (hardcoded per built-in)**

- `claude` → `--continue`
- `codex` → `resume`
- `gemini` → not supported (action hidden)
- custom agents → not supported (action hidden)

**Behaviour**

Reuses `launchAgent(folder, agent)` with `agent.args` replaced by the resume args. Environment, command, and terminal handling are otherwise unchanged.

### F3. Ask about this repo (one-shot)

**UX**

- `FolderActions` gets an `Ask About This Repo` action.
- Visibility rule: shown only when at least one headless-capable agent is enabled (see "Headless capability" below).
- The action pushes an `AskForm` (`Form`) with:
  - `Preset` (dropdown, optional) — the four F1 built-in prompts as options plus `Custom`.
  - `Question` (text area, required) — pre-filled from `Preset` when a preset is selected; freely editable.
- Submit pushes an `AskDetail` (`Detail`) with `isLoading` while the CLI runs.
- `AskDetail` markdown structure:
  - First line: `> Answered by **<Agent name>** in \`<repo path>\``
  - Then the raw response from stdout.
- `AskDetail` actions: `Copy Response`, `Ask Again` (pops back to `AskForm` with question preserved), `Close`.

**Agent selection**

1. If the folder has a recorded last-used agent AND that agent is headless-capable AND still enabled → use it.
2. Else use the first enabled headless-capable agent in the order `claude`, `codex`, `gemini`.
3. If neither yields a match, the `Ask About This Repo` action is not shown.

**Invocation**

- Split the template into argv first, then substitute the placeholder in each element:
  ```ts
  const argv = splitArgs(agent.headlessArgsTemplate).map(a =>
    a.replace('{{prompt}}', prompt)
  );
  execFile(agent.command, argv, { cwd, env: mergedEnv, timeout: 120_000 });
  ```
  Splitting before substitution keeps quoting safe when the prompt itself contains spaces, quotes, or newlines.
- `cwd` is the repo root when the folder is inside a repo, else the folder itself (matches existing launch behaviour).
- On non-zero exit, or timeout, or empty stdout: show failure toast and render stderr (or a canned message) in the detail body.

### F4. AI commit message

**UX**

- `FolderActions` gets an `AI Commit Message` action.
- Visibility rule: shown when the folder is inside a Git repo AND at least one headless-capable agent is enabled. Dirty-only gating is skipped because the diff check happens on invocation (simpler than re-computing dirty state for visibility).
- Action flow:
  1. Read `git diff --cached` in the repo root.
  2. If empty, `confirmAlert` asking "No staged changes. Use unstaged diff (`git diff HEAD`) instead?". On cancel, abort.
  3. If the chosen diff is empty, error toast "No changes to summarize" and abort.
  4. If diff exceeds 50_000 bytes, truncate to 50_000 bytes and append `\n\n[diff truncated at 50KB]`.
  5. Show animated toast "Generating commit message…".
  6. Call the headless agent (same selection rule as F3) with the fixed prompt below.
  7. Trim response. Copy to clipboard via `Clipboard.copy`. Replace toast with success toast whose `message` is the first line of the response.

**Fixed prompt template**

```
Write a git commit message for the following diff.

Requirements:
- Use Conventional Commits format: `<type>(<scope>): <subject>`.
- Subject line max 72 characters, imperative mood.
- Then a blank line, then a body wrapped at 72 characters explaining WHY, not WHAT.
- Output ONLY the commit message. No code fences, no preamble, no explanation.

Diff:
<DIFF>
```

Where `<DIFF>` is replaced with the (possibly truncated) diff text. F4 uses the same `runHeadless` path as F3 — the fully-composed prompt (instructions + diff) is passed as a single argv element via `execFile`, no shell involved. Not passed via stdin.

## Data & type changes

Extend the local `Agent` type in `src/vibe.tsx`:

```ts
type Agent = {
  id: string;
  name: string;
  command: string;
  args: string;
  icon: Icon;
  description: string;
  env?: string;
  resumeArgs?: string;            // NEW — enables F2 when set
  headlessArgsTemplate?: string;  // NEW — enables F3/F4 when set; contains "{{prompt}}"
};
```

Populated in `agents()`:

- `claude`: `resumeArgs: "--continue"`, `headlessArgsTemplate: '-p "{{prompt}}"'`
- `codex`: `resumeArgs: "resume"`, `headlessArgsTemplate: 'exec "{{prompt}}"'`
- `gemini`: `headlessArgsTemplate: '-p "{{prompt}}"'` (no resume)
- customs: neither field set

New type:

```ts
type PromptTemplate = {
  id: string;      // "builtin:*" or "custom:<uuid>"
  title: string;
  prompt: string;
};
```

## Storage additions

- `vibe-prompt-templates` — `PromptTemplate[]` (custom only). Serialized as JSON.
- No changes to existing keys (`recent-vibe-folders`, `pinned-vibe-folders`, `last-vibe-agents`).

## Module layout

`src/vibe.tsx` is already ~1000 lines. To avoid pushing it past the point of being hard to reason about, this work extracts new logic into sibling files rather than piling on:

- `src/vibe.tsx` — unchanged top-level `Command`, wires in the new actions on `AgentPicker` / `FolderActions`.
- `src/agents.ts` — pure helpers: `agents()`, `headlessCapableAgents()`, `pickHeadlessAgent(folder, lastAgentId)`, `Agent` and `PromptTemplate` types. Moved out of `vibe.tsx`.
- `src/templates.ts` — built-in templates constant, `loadTemplates()`, `saveTemplates()`, `deleteTemplate()`, `upsertTemplate()`.
- `src/headless.ts` — `runHeadless(agent, prompt, cwd)`: single-purpose function that runs an agent's headless template and returns `{ stdout, stderr, exitCode }`. Handles 120s timeout, arg splitting, env merging.
- `src/views/TemplateList.tsx`, `src/views/TemplateForm.tsx`, `src/views/AskForm.tsx`, `src/views/AskDetail.tsx` — new React views.

Existing helpers that F2/F3/F4 also need (`launchAgent`, `parseEnv`, git helpers, `openInTerminal`) stay in `vibe.tsx` for this release and are imported by the new views. Extracting them further is out of scope.

## Error handling

| Case | Behaviour |
|------|-----------|
| Headless CLI timeout (>120s) | Failure toast "Agent timed out". `AskDetail` body: "Agent did not respond within 120s." |
| Headless non-zero exit | Failure toast "Agent failed". `AskDetail` body: last 4KB of stderr (or "No error output"). |
| Empty stdout | Failure toast "Agent returned no output". |
| Missing headless-capable agent | F3/F4 actions not shown. |
| `git diff` failure | Reuse existing `gitErrorMessage` → failure toast. |
| Diff empty (both staged and unstaged) | Failure toast "No changes to summarize". |
| Template save failure (rare) | Failure toast "Could not save template". Form stays open. |
| Prompt shell-quoting | F1 passes the prompt through `shellQuote` before concatenating into the args string that reaches the terminal. F3/F4 use `execFile` with an argv array, so no shell quoting is needed — the prompt is a single argv element. |

## Testing

The repo has no test suite and this release does not add one. Verification is:

- `npm run lint` — clean.
- `npm run build` — clean.
- Manual smoke pass per feature (checklist below).

### Manual smoke checklist

1. **F1 happy path** — pick a project, `Launch Claude with Prompt…`, pick "Summarize this repo", Claude opens in Terminal with the prompt as its first message.
2. **F1 custom** — create a template, launch with it, delete it.
3. **F2** — launch Claude in a project, exit, reopen Vibe, run `Resume Last Agent`, Claude continues the prior session.
4. **F2 negative** — repo whose last agent was Gemini → action hidden.
5. **F3 happy path** — pick a project, ask "What does this repo do?", receive markdown answer sourced from the last-used agent.
6. **F3 timeout** — temporarily hardcode the timeout to 2s in dev build, ask a question that takes longer, confirm timeout toast + detail message. Restore before shipping.
7. **F4 staged** — stage a change, run `AI Commit Message`, clipboard has a well-formed conventional commit.
8. **F4 unstaged fallback** — unstaged changes only, confirm the fallback prompt, then success.
9. **F4 no changes** — clean repo, action shows "No changes to summarize".
