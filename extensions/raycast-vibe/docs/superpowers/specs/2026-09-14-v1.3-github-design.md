# Vibe v1.3 — GitHub Integration

Adds a GitHub dashboard to Vibe (open PRs for the repo, issues assigned to me, PRs where I'm requested for review) and a safe "Create Pull Request" action. All GitHub interaction goes through the local `gh` CLI — no tokens stored in Vibe, no cloud backend.

## Goals

- Show the day-to-day GitHub queue for a project (open PRs, assigned issues, review requests) without leaving Raycast.
- Provide a one-action path to open a draft PR in the browser from the current branch.
- Preserve Vibe's local-first posture: no API keys stored, no network state beyond `gh`, no cloud accounts required by Vibe itself.

## Non-goals

- Checkout PR as worktree. (Depends on v1.2 features not yet on main. Defer to v1.4.)
- PR comments, review submission, approvals, merges from Vibe. (Higher risk; browser is fine for now.)
- Non-GitHub forges (GitLab, Bitbucket, Gitea).
- Configurable `gh` binary path preference.
- Caching or background polling.

## Dependency

The local `gh` CLI (`https://cli.github.com/`). Vibe does not bundle it; the user installs and authenticates via `gh auth login` before Vibe can show anything.

Vibe never stores GitHub tokens. All auth is delegated to `gh`.

## Features

### G1. GitHub dashboard

New action in `FolderActions`: **GitHub**. Gated on:
- `folder.repositoryRoot` is set, AND
- `folder.remote` matches `github.com` (Vibe already detects this; reuse the same logic as `Open GitHub Repository`).

Pushes `GitHubDashboard` — a `<List>` with three sections:

1. **Open Pull Requests** — `gh pr list --repo <owner/repo> --state open --json number,title,url,author,headRefName,isDraft,statusCheckRollup,mergeable,updatedAt`
2. **My Assigned Issues** — `gh issue list --repo <owner/repo> --assignee @me --state open --json number,title,url,updatedAt`
3. **Reviews Requested** — `gh pr list --repo <owner/repo> --search "review-requested:@me is:open" --json number,title,url,author,headRefName,statusCheckRollup,updatedAt`

The three fetches run in `Promise.all`. A single failure surfaces a per-section toast but does not block other sections from rendering.

The owner/repo pair is derived from the git remote URL (parse `origin` remote once at view load).

**Rendering:**

Each PR item:
- Title: `#<number> <title>`
- Subtitle: `@<author>  ·  <headRefName>`
- Accessories: mergeable state (icon), CI rollup (checkmark / cross / hourglass / question), draft badge, relative updated time.

Each issue item:
- Title: `#<number> <title>`
- Accessories: relative updated time.

**Per-item actions:**
- **Open in Browser** (default) — `openUrl(item.url)`.
- **Copy URL**.
- For PRs: **Copy Branch Name** (`headRefName`).
- **Refresh** (dashboard-level).

Root ActionPanel:
- **Refresh** — reruns the three fetches.

### G2. Create Pull Request

New action in `FolderActions`: **Create Pull Request**. Same gating as G1.

Runs `gh pr create --web` inside the repo root:
- This opens the GitHub PR-creation draft page in the browser without publishing.
- Requires the current branch to be pushed to origin (and to have commits ahead of the base).
- Vibe never pushes on the user's behalf; if `gh` errors with "no upstream" or "no commits between", surface an actionable toast:
  - "Push the branch to origin first (`git push -u origin <branch>`)."

## Auth / availability handling

Before the dashboard fetches, run `gh auth status --hostname github.com` once. Three outcomes drive three view states:

| `gh` state | Dashboard body |
|------------|----------------|
| `ok` | Normal list with three sections. |
| `unauthenticated` | Empty state message: "GitHub CLI is not authenticated. Run `gh auth login` in a terminal and reopen this view." with an **Open Terminal Here** action reusing the existing `openInTerminal(repoRoot, "gh auth login")` helper. |
| `missing` (`gh` binary not found, `ENOENT`) | Empty state message: "GitHub CLI (`gh`) is not installed. Install it and reopen this view." with an **Open Install Docs** action to `https://cli.github.com/`. |

The `Create Pull Request` action shows a friendly toast for the same three outcomes.

## Module layout

- `src/github.ts` — pure helpers wrapping the `gh` CLI. Single responsibility: JSON in, typed data out.
  - Types: `type PullRequest`, `type Issue`, `type GhCheckStatus`, `type GhAvailability = "ok" | "unauthenticated" | "missing"`.
  - `ghAvailability(): Promise<GhAvailability>` — runs `gh auth status --hostname github.com` and classifies stderr / exit code / ENOENT.
  - `resolveGitHubRepo(repoRoot): Promise<{ owner: string; name: string } | undefined>` — derives from `git -C <repoRoot> remote get-url origin`. Handles both `git@github.com:owner/name.git` and `https://github.com/owner/name(.git)?`.
  - `listPullRequests(repoRoot, repo): Promise<PullRequest[]>`
  - `listAssignedIssues(repoRoot, repo): Promise<Issue[]>`
  - `listReviewRequests(repoRoot, repo): Promise<PullRequest[]>`
  - `createPullRequestWeb(repoRoot): Promise<void>` — runs `gh pr create --web` with cwd = repoRoot.
- `src/views/GitHubDashboard.tsx` — three-section list view. Handles the availability branch and per-section fetch errors.
- `src/vibe.tsx` — wire two new actions in `FolderActions` (GitHub, Create Pull Request), each gated on `folder.repositoryRoot` and a GitHub remote.

Existing helpers reused: `openUrl`, `openInTerminal`, `git` (the low-level runner) — export from `vibe.tsx` if not already exported.

## Error handling

| Case | Behaviour |
|------|-----------|
| `gh` missing (`ENOENT`) | Dashboard renders "install gh" empty state; Create PR toast: "GitHub CLI (`gh`) is not installed." |
| `gh` unauthenticated | Dashboard renders "run gh auth login" empty state; Create PR toast: "Run `gh auth login` first." |
| Section fetch fails | Failure toast for that section only; other sections still render. |
| `resolveGitHubRepo` fails (non-GitHub remote / no origin) | Actions hidden via the folder-level gate; if somehow reached, dashboard shows a message + close action. |
| `gh pr create --web` fails (no upstream, no commits) | Failure toast with the actionable message quoted above. |
| Rate-limit response from GitHub | `gh`'s stderr is surfaced verbatim in the toast (contains the rate-limit reset time). |

## Storage

None. `gh` and git are the source of truth. No LocalStorage keys.

## Testing

No test suite (repo has none). Verification = `npm run lint && npm run build`. Manual smoke:

1. **G1 happy path** — open Vibe on a public GitHub repo, action **GitHub** → dashboard renders three sections; each PR shows CI status accessory.
2. **G1 empty repo** — private repo with no PRs / issues / review requests — three empty sections, no error.
3. **G1 gh missing** — with `gh` renamed out of PATH temporarily — dashboard shows install message.
4. **G1 gh unauthenticated** — after `gh auth logout` — dashboard shows auth message.
5. **G1 non-GitHub remote** — repo with only a GitLab remote — both **GitHub** and **Create Pull Request** actions hidden.
6. **G2 create PR happy** — on a pushed branch with commits ahead — browser opens draft.
7. **G2 unpushed branch** — actionable toast about pushing to origin.
8. **G2 unauthenticated** — actionable toast about `gh auth login`.
