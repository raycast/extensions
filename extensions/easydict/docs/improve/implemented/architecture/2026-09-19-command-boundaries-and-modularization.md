# Agent Note: Easydict 重构路线图

Status: implemented

## Problem

查询、收藏和 Provider 管理的依赖边界与业务归属不完全一致，跨功能出口还会把无关执行实现带入独立命令。需要同时降低命令依赖成本、重复职责和维护复杂度。原计划将架构调整、协议简化、回归修复和 API 评估放在一份文档，难以分别交付和验收。

## Decision

本轮按每个命令的实际依赖建立边界，完成下面 10 个工作项的实施或评估。查询、收藏和 Provider 管理归入 features；共享配置归入 providers/profiles；结果契约与渲染归入 core/results；通用基础工具归入 shared。展示由原始 Provider 结果同步推导，缓存继续保存原始结果，收藏继续保存最终快照。06 的 useForm 原型评估后未采用；10 随相关重构分批交付。每项的代码证据、取舍及专项验收在对应记录中维护。

初版方案经独立 subagent 审查；实施时将互不依赖的工作分配给 subagent，并由主代理逐阶段 review，再进行 find-code-simplifications 审查、修正、验证和提交。Raycast 官方文档、API 更新记录、安装包实现及实际产物均纳入判断；不因存在官方 hook 就替换已有正确的业务生命周期。

## Shared constraints

- 保留 macOS 与 Windows，守卫平台 API、路径和 shell。命令名称、主次动作、快捷键和根导航保持现状；07 仅对已确认的冲突做明确修复。
- Raycast 各命令独立打包；源码复用不意味着共享 JS 单例。默认 Cache 和 LocalStorage 数据可跨命令使用，实例内队列、pending Promise 与缓存代次的作用域不因搬目录而扩大。
- 最新请求独占流式更新、最终结果、缓存写入与 loading 清理；清空前启动的请求不能回填缓存。请求代次、服务请求 ID、缓存清空代次、列表代次和选择锚点保留各自职责。
- 保留 `providerKey` 与 `serviceId` 的区分、晚加载服务加入规则、已有 ID 下次查询应用配置及重生成使用最新配置；具体契约由 02 维护。
- 静态设置与凭据使用 Preferences，动态 profiles 使用加密 LocalStorage。保留 [repository](../../../../src/providers/profiles/repository.ts) 实例内写队列和 [configuration](../../../../src/providers/profiles/configuration.ts) 的加载去重；JSON 回退也是配置写入者，命令重开读取持久化数据。
- 配置与收藏的存储键、字段、枚举和格式保持兼容，保留异常或不支持的存储内容供恢复；收藏独立于查询缓存。Provider 缓存与最终收藏展示快照的分界由 09 维护。
- 基类继续拥有计时、取消及最终错误规范化；Provider 保留 payload、解析和词典 sections。共享协议函数必须有实际多个消费者。
- 官方 hooks 按语义采用，付费查询缓存命中不能因引入 SWR 额外请求，也不能丢失清空保护；完整依据见 API 审查。

## Verification and completion

每个代码交付完成 `npm run lint`、`npm test`、`npm run build` 和 `git diff --check`。迭代中用针对性测试，最终检查通过后仅因后续修改或未解决失败重跑。回归修复先证明失败再证明通过；测试真实解析、缓存和迁移，在 Raycast 或网络边界 mock，不测试纯搬迁细节。

按 10 同批记录测试的删除依据及保留/替代入口，优先减少未执行夹具、模拟的业务规则和中间实现断言；不以用例数下降为目标。持久化兼容、请求所有权、缓存清空、跨平台与外部协议测试不能因名称或断言相似而整体删除。

原生验证按工作项范围执行，分别记录 macOS/Windows、桌面版本和 API/utils 包版本，以及未验证路径；mock 不替代显示、快捷键或生命周期结论。目录迁移同步 AGENTS 和链接；用户可见变更同步 README 与中文说明，内部重构不进入用户 changelog。

只读调查基线为 42 个测试文件、260 个测试通过；最终实现为 43 个测试文件、299 个测试通过。01 保存构建与运行基线，其他记录保存各批次证据。各工作项已按 [文档约定](../../README.md) 移至 implemented 或 rejected，并修复相互引用。

## Deferred work

- `profile.order` 持久化去重：仍有缺省排序消费者，另行明确缺省、补全与转换策略后处理。
- 检测器局部快照：需明确每次查询读取设置的时机，并验证重叠调用、取消、远端共识与本地回退；不直接合并 settled 和结果收集终止标记。
- 图标单一目录：有减少名称、资源与下拉项重复的潜力，但须保留顺序、tint 和 fallback，不作为主线前置条件。
- Provider 原始 result 裁剪：AI 表单测试仍读取它，缓存也涉及序列化，另行确定契约后再做。
- Swift OCR 集成、AI tools、help.md 和依赖升级保留在 API 审查中作为独立候选；没有证据时不扩大范围。
- 全仓一次性迁移、历史迁移清理、存储格式变更和尚未复现的跨命令写锁不属于本轮。

## Alternatives considered

**保留一份大计划。** 实施状态与局部风险难以追踪，尤其 C 批次本来就包含五项不同工作，改为按交付拆分。

**按每个目录或文件拆提案。** 会把一个行为变更拆碎；以可独立审查和验证的结果为边界，08 内允许多个机械迁移批次。

**把所有提案串行设为依赖。** OpenAI、Bing、模型目录和快捷键互不构成技术前置条件；仅约束同一区域的先后，避免额外等待。

## Risks

**边界回流。** 单项通过后仍可能被新的 import 带回无关依赖，01、02、08 的交付都需检查实际产物。

**多份事实漂移。** 子提案是局部范围与验收的唯一维护位置，API 审查保存依据，本文只维护路线图和共同行为。

**组合回归。** 服务装配、公共契约与展示投影分别正确不保证组合正确，09 后仍需对整体查询与收藏流程复核。
