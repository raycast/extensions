## Deferred findings

- Query generation IDs, unified cancellation, and stale provider completion are
  higher-impact correctness work, but they need a dedicated behavioral plan and
  are intentionally excluded from this easy-cleanup batch.
- Splitting `QueryWordInfo`, consolidating `QueryResult` wrappers, separating
  dictionary formatters, and reorganizing Youdao response types are larger
  architectural changes that require characterization coverage first.
- Removing `DisplaySection<T>` / `ListDisplayItem<T>` generics is deferred even
  though plan 003 removes their unused payload fields; the generic change
  propagates through provider formatting APIs and is not a mechanical cleanup.
- Simplifying the Promise/AsyncGenerator translation contract and removing
  `StreamChunk.role` are deferred until the streaming protocol is reviewed as a
  whole.
- The embedded shared Caiyun credential, vulnerability-reporting policy, and all
  GitHub Actions changes are frozen by maintainer direction and must not be
  touched by these plans.

## Findings considered and rejected

- “Identical preferred languages crash during fallback selection” was rejected
  after direct verification. `src/easydict.tsx` calls
  `checkIfPreferredLanguagesConflict()` before rendering `SearchWord`, and
  `src/features/search/LanguageConflictError.tsx` presents a blocking error when
  the two configured languages match. The unsafe cast in
  `getAutoSelectedTargetLanguageItem()` can be revisited when query/language
  types are redesigned, but it is not currently a reachable user-facing crash.
- Unifying `TranslationServiceConfig`, `DictionaryServiceConfig`, and
  `DetectServiceConfig` was rejected. Their provider protocols and capabilities
  differ materially; a generic service-config abstraction would add type
  parameters without removing meaningful duplication.
