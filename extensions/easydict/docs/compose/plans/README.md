## Findings considered and deferred

- Cancelling losing language-detection providers after a winner is selected is
  useful quota/performance work, but it is separate from preventing stale query
  commits. Revisit it after 006, when each query already owns one clear signal.
- The orphaned Apple/Google detection model and stale detection documentation
  need a product decision (restore versus retire), so they are not bundled into
  a correctness fix.
- Eager construction of per-row action trees may affect large dictionary result
  rendering, but it needs profiling evidence before a refactor plan.
- Larger type and formatter reorganizations remain deferred until the test
  baseline covers their current behavior.

## Findings considered and rejected

- Unifying translation, dictionary, and detection service-config types remains
  rejected: their protocols and capabilities differ materially, so a shared
  generic would obscure rather than remove complexity.
- Provider-specific response types and parsers are not duplication to remove;
  provider isolation is an explicit repository architecture constraint.
