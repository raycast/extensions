# Existing Slack AI tools

Reviewed against `package.json`, `ai.yaml`, and every file in `src/tools/` on September 24, 2026. There are 17 registered tools with 36 top-level inputs, plus the unregistered `message-signature.ts` helper. `?` means optional. These are the only tools available to the bundled skills; interactive commands do not add AI capabilities.

## Readers and search limits

- All tools use the extension's configured OAuth or access-token client. There is no workspace-selection input, authenticated-user profile reader, or authoritative timezone reader. `find-users` and `get-users` return timezone display labels, which are not a reliable replacement for a user-specified timezone. Slack's supported `from:me` search modifier scopes the standup to the authenticated user's activity without inventing a profile tool.
- `get-channels` internally pages public/private nonarchived channels and returns ID, name, purpose, and topic. It omits privacy flags, membership, workspace metadata, and DM listings. Match exact names instead of inferring visibility or using the first substring match.
- `get-channel-history.text` is a channel name or a C-prefixed ID, not message text. Direct D/G IDs fail its ID validator and fall through to name lookup. Name lookup chooses an exact name first, otherwise its first substring match. The skills resolve channels first to avoid ambiguity. `after` becomes an oldest timestamp; the tool always requests 30 messages and drops pagination metadata, thread IDs, and reply counts. It extracts text from message text, attachments, or simple block text.
- `read-conversation` accepts a C/D/G conversation ID, U/W user ID, or Slack message permalink. Passing a user ID opens or resumes that DM. `limit` defaults to 30 and caps at 100; `after` must parse as an ISO timestamp. It returns channel, messages, and pagination indicators, but accepts neither cursor nor end-time input. Message records contain text, raw user ID or bot identity, exact `ts`, `threadTs`, `replyCount`, date, and file metadata. Empty top-level text does not trigger the richer attachment/block fallback in this reader.
- A permalink makes `read-conversation` call `conversations.replies` using the message timestamp encoded in `/p...`. The parser ignores `thread_ts` in the URL query. A reply permalink can therefore fail when its own timestamp is treated as the parent. If the URL has a parent `thread_ts`, pass that exact value to `read-thread` instead. Otherwise use an independently established parent or report the missing context. For a known parent permalink, split the digits after `p` before the last six digits to recover the exact Slack timestamp, preserving it as a string.
- `read-thread` accepts exact parent `threadTs`, `channel`, optional `cursor`, and a `limit` defaulting to 50 and capped at 100. It returns messages plus `hasMore`, `nextCursor`, `returnedCount`, and effective limit. Follow the returned cursor when needed; stop and report `hasMore` without a usable continuation. Text falls back through attachments/blocks, but the reader replaces author IDs and mentions with display names. Names may collide, so retain identity evidence from search or `read-conversation` when attributing a person's work.
- `search-messages` accepts only a query string and `sort`, defaulting to score. It calls `search.messages` with a fixed count of 100. The loop increments `page` once in the request and again after checking continuation, so it requests pages 1, 3, 5 and can omit the final page as well. No page, count, cursor, direction, semantic mode, public-only flag, or file-search input is exposed. Its output also drops totals and continuation metadata. Narrow queries can reduce missing coverage but cannot establish an exhaustive audit. The tools are unchanged by this skill-only addition.
- Search results contain `channelId`, `channelName`, rounded millisecond `timestamp`, display `time`, `userName`, `user`, `score`, `message`, search `messageId`, and `permalink`. They do not expose raw `ts`, `thread_ts`, reply counts, or files, despite a download-tool comment mentioning search files. The timestamp truncates Slack's fractional seconds before converting to milliseconds. Never pass it or the search identifier as a Slack message timestamp; use exact read results or a verified permalink.
- `find-users` internally pages the directory and matches name, username, display name, or email case-insensitively, excluding deleted users and bots. `get-users` reads only the first 1,000 users and discards continuation, returning a smaller identity/status projection. Neither tells which user is the authenticated caller. `get-emojis` returns the workspace's custom emoji mapping.
- `formatSlackFiles` returns only file ID, name, MIME/type, and size. `download-files` saves bytes locally and returns paths, not document text. There is no registered tool for reading those local documents, fetching linked web pages, or retrieving a file's parsed content. Summaries must not infer contents from attachment titles.

## Mutations and helpers

- `send-message.recipient` accepts a C/D/G conversation ID or U/W user ID. User IDs are resolved to DMs before sending. Nonempty `text` is required. The result contains channel, exact `ts`, text, and a permalink when available. Sending may succeed before the following permalink request fails. There is no idempotency-key input; inspect an uncertain destination before retrying.
- `reply-thread` requires channel, exact parent `threadTs`, and nonempty text. `replyBroadcast` defaults to false. It returns channel, parent/thread timestamp, reply timestamp, text, and broadcast state, without a permalink. Broadcast is a separate audience change and is never inferred from a request to reply.
- `update-message` replaces the authenticated user's existing message text and Block Kit blocks; it is not a partial edit. It returns channel, exact timestamp, text, and optional permalink. `add-reaction` normalizes an emoji name by stripping surrounding colons and returns the message reference. Neither action is part of the three skills' default read/draft workflows.
- The unregistered [message-signature.ts](../../src/tools/message-signature.ts) helper renders message text and the optional Raycast signature. At up to 3,000 characters it can use a Markdown block; longer content uses bounded section/mrkdwn blocks. Disabling the signature falls back to text-only messages. File uploads explicitly use section/mrkdwn rather than Markdown blocks. This helper is not callable as an AI tool, and there is no native Slack composer-draft tool.
- `open-group-dm.userIds` is a string, parsed on commas or whitespace and deduplicated. It requires 2 to 8 other U/W user IDs and opens/resumes the group. The caller must exclude the authenticated user. It returns channel and users; it does not send a message.
- `get-huddle-link` accepts a conversation or user ID, resolving a user to a DM and reading workspace metadata. It returns workspace ID, channel, and a join URL. It does not fetch transcripts or create a meeting record.
- `upload-files.channel` must be C/D/G, never U/W. `filePaths` contains absolute paths separated by actual newlines. Optional text accompanies the upload; optional `threadTs` targets the parent thread. It uploads files as-is and returns file IDs/names/links and a message permalink when available. A failed operation may leave a partial side effect, so do not retry blindly or re-encode files to bypass errors.
- `download-files.fileIds` is a newline-separated string of Slack F-prefixed IDs. `destinationDir` is optional; the default is Downloads, and a leading tilde is expanded. Results contain ID, name, path, and byte count. This is a filesystem write and is not needed for these text-based skills.
- `set-status` needs `text` and `emoji` together for a status change; both empty strings clear it. `duration` is nonnegative integer seconds; omission or zero means no expiry. `snoozeMinutes` is a nonnegative integer in minutes, with zero ending snooze. Omit it to leave snooze unchanged. Status and snooze changes can succeed independently; neither belongs to digest or standup drafting.
- No registered tool saves a Slack draft, schedules messages, exposes unread/read markers, creates tasks/reminders, lists channel members, or switches workspaces. Native commands with related names are not tool substitutes. Explicitly requested unsupported operations stop with the gap reported.
