# Azure DevOps Repository Search

## [Add Create Work Item command and sprint fields] - {PR_MERGE_DATE}
Added a "Create Work Item" command that opens the work item form directly; the "New Work Item" action of My Work Items is unchanged. The form can now also, for the project set in the preferences, plan the item in a sprint, pick its parent from that sprint's backlog items, and set an estimate in hours; for any project it can also set the Area. All new fields are optional. The estimate uses the Custom Estimate Field when it is configured. The command has optional defaults (project, type, area, sprint, assignee, create branch) that hide those fields from its form.

## [Add Search Work Items command and more work item actions] - {PR_MERGE_DATE}
Added a "Search Work Items" command to find any work item of the project by number or by words in its title or description. My Work Items now also offers, in new sections at the end of the action panel, adding comments, logging hours, moving items to another sprint, showing related work items, pull requests and commits, and copying the description or comments. Existing actions and shortcuts are unchanged.

## [Add Sprint Work Items command] - {PR_MERGE_DATE}
Added a "Sprint Work Items" command: browse the work items of the current or any other sprint in the same order and hierarchy as the sprint backlog, grouped by User Story or by state, with story points and hours when the process has them. Add comments, log hours, move items to another sprint, see related work items, pull requests and commits, and copy descriptions or comments as Markdown or plain text. New optional preferences: Team (defaults to the project's default team) and Custom Estimate Field. The work item detail, change state and branch views are now shared between My Work Items and Sprint Work Items, with no change in behavior.

## [Optional assigned-to-me filter for My Work Items] - 2026-09-10
Added a setting to My Work Items to browse work items assigned to anyone, not just yourself. It is on by default (assigned-to-me only); when turned off, a project, state, or type filter is required to keep the result set bounded, and each item's assignee is shown in the list.

## [Fix My Work Items settings not saving] - 2026-06-24
Fixed the My Work Items setup form silently discarding selections (project, states, types, default repository, default base branch) that were made while option lists were still loading, which caused Save to persist the defaults.

## [Customisable work item state order] - 2026-06-15
Added a "Preferred State Order" setting to My Work Items so you can pin states (e.g. "Doing, In Progress") to the top of the list in your own order; unlisted states follow afterwards.

## [Add Windows support] - 2026-06-15
Declared the extension as cross-platform (macOS and Windows). All commands rely only on cross-platform APIs; the work item "Show in Finder" action now reads "Show in Explorer" on Windows.

## [Add My Work Items command] - 2026-06-04
Added a "My Work Items" command: browse work items assigned to you across projects, filter and group by state/type/project, change state on single or multiple items, view descriptions with inline images plus acceptance criteria, repro steps, comments and attachments, create new work items, and create branches linked to a work item.

## [Add PBI Copy Work Item Id] - 2025-09-01
Added the ability to copy the work item ID of a PBI.

## [Add PBI, PR, and pipeline search] - 2025-03-27
Added PBI, PR, and pipeline search

## [Add Menu PR items] - 2025-02-17
Added the projectfilter

## [Add Menu PR items] - 2024-04-13
Added the PR menu.

## [Simplified PAT] - 2024-04-11
Made the usage of a PAT less complex. The PAT generated by Azure DevOps could be used right away.

## [Initial Version] - 2024-03-31
The first version of the Azure DevOps Repository search extensions. This will help you find repo's quickly, open them or copy the GIT remote.
