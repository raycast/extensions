## Decisions so far

- [Can Node read the exit IP claude.ai sees?](issues/01-claude-exit-ip-source.md) — Yes. `https://claude.ai/cdn-cgi/trace` returns the Cloudflare trace block to bare `curl` (200, ~0.4s, no browser UA, no challenge); `ip=` is the exit IP and `loc=` gives the country free. Verified against a neutral endpoint that returned a different IP in a different country, so the split-routing premise holds.

- [Raycast Store rules for a Claude-branded extension](issues/03-store-rules-and-manifest.md) — No trademark or logo policy exists; verbatim vendor marks ship widely (`extensions/claude` uses the bare "Claude" title and Anthropic's unmodified wordmark). `license: "MIT"` is a schema enum with 3105/3105 compliance. Plain HTTP and undocumented vendor endpoints both have shipped precedent (`china-ip-address` fetches Alibaba's `getip.php`). **Constraint for [06](issues/06-identity-and-manifest.md): the single-command naming rule forbids a bare `"title": "Claude"`** — it must be function-qualified, `China IP Address` / `GitHub Status` shaped.

- [Which geo provider enriches one IP?](issues/02-geo-provider-options.md) — `https://ipwho.is/<ip>?fields=…` recommended: keyless, HTTPS, all four card fields, 30/30 probes at 0.51–0.59s, IPv6 at parity, no robots.txt, Store precedent. `api.ip.sb` is the fallback and the only provider matching the reference card's wording verbatim. **`ip-api.com` is out** — HTTPS returns 403 and its terms are non-commercial only, so the sibling extension's provider cannot be reused. Richer `ipapi.is` rejected on a measured ~10% multi-second stall rate.

- [Exit-IP source and fallback chain](issues/04-source-and-fallback-decision.md) — `claude.ai/cdn-cgi/trace` only, no fallback host (a different host's IP would answer a different question under the same label). Valid iff `^ip=` parses as an IP **and** `h=claude.ai` — the `h=` check proves the answer came from Claude's edge, not a middlebox. Three states: **OK** / **blocked** (response arrived, validation failed — carries the status code) / **unreachable** (no response, timeouts included). 5s budget via `AbortSignal.timeout`. Code written fresh, ipcheck-ing credited as prior art without an MIT notice.

- [Geo provider and failure behaviour](issues/05-geo-decision.md) — `ipwho.is` only, fixed, keyless, bare fetch; the client branches on the **`success` boolean**, never `response.ok` (a reserved IP returns 200 + `success:false`, the trap the sibling falls into). Line is country · city · `connection.isp` — region and ASN dropped from display, ASN still fetched for a Copy action. Flag computed locally, one function for both paths. **Geo failure degrades, never errors**: flag + country from the trace's own `loc=` (name via built-in `Intl.DisplayNames`), explicitly marked partial so a rate-limited card can't pass for a correct one; over-quota needs no rule of its own. Progressive render — IP paints at ~0.4s, geo fills in on its own 5s budget. No provider preference. IPv6 needs no special handling; the robots.txt question is moot for this provider.

- [Extension identity and manifest](issues/06-identity-and-manifest.md) — `claude-exit-ip` / **Claude Exit IP**; one `view` command `Show Exit IP` in `src/index.tsx`, no subtitle. "Exit IP" over "IP Address" because the per-destination framing is the only thing separating this from the four IP extensions already on the Store. Icon is Anthropic's sunburst verbatim on clay, one asset, no `@dark` twin — a legal-comfort call, since 03 found no Store policy either way. No `preferences` at all. Deps taken from the corpus tip (`@raycast/api ^1.104.23`, `@raycast/utils ^2.2.7`), **overriding this ticket's own instruction** to copy ipcheck-ing, which is two majors stale; no `node-fetch`, no `engines`. Three caveats recorded rather than decided: the `marcuslannister` handle is unverified as a *Raycast* handle, Anthropic's own trademark policy was never read, and the icon PNG must be rendered from Anthropic's brand SVG, not copied from a sibling extension.

- [The card: layout and states](issues/07-card-prototype.md) — `Detail`, markdown only, **no metadata panel**: H1 flag + IP, location line, rule, caption. Four variants were built and cycled live in Raycast; the metadata panel lost because it restates the prose line and halves the ISP's width. **One flag per card, in the H1 next to the IP, never next to the country name** — a user correction that overrides 05's illustrative `🇺🇸 United States · …` line (05's substance stands, only the flag's position moves). Six states drawn, not four: the loading line paints the **country immediately** from the trace's own `loc=` and grows in place when geo lands, so no `Locating…` ever shows; the partial marker sits **inline** after the country; failure cards keep the same four slots but swap the caption for a **provenance footer** (`claude.ai/cdn-cgi/trace · HTTP 403`), which is where 04's status code surfaces. Screenshot parity deliberately not pursued. Prototype at `.scratch/claude-exit-ip/prototype/`, throwaway, delete once 10 is written.

- [Actions and error copy](issues/09-actions-and-copy.md) — Four actions: Copy IP (`⏎`), Copy IP + Location (`⌘⇧C`), Copy ASN (`⌘⇧A`), Refresh (`⌘R`); *open claude.ai* and *open a lookup page* cut. All copies via `Action.CopyToClipboard` for Raycast's own HUD, so no custom success toast — and **no toasts at all**: both failure cards already state the failure at three levels, so a toast would overlay the message it duplicates. Clipboard carries **no flag emoji** (tofu in terminals and commits). Actions are per-state under one rule — **never copy a value still in flight, never copy a value you don't have** — which hides Copy IP + Location during `ip-only` but keeps it, sparse, on `geo-failed`; Refresh is primary on both failure cards, the action their bodies just told the user to take. Five slots worded: caption `The IP claude.ai sees you from`; partial marker `— location lookup failed`, cause-agnostic, chosen over 07's `— country only` because that phrase reads as a legitimately sparse result, the exact thing 05 forbade; *Something answered, but not Claude* / *Couldn't reach claude.ai* with bodies that name the suspects but never guess which, never blame Anthropic for a hotel wifi page, and never cite the 5s timeout (most unreachable causes return instantly). **Three provenance footers, not 07's two** — blocked fires on 2xx too, so `HTTP 200 · not a claude.ai trace` is where 04's `h=` check surfaces. Loading H1 is **empty**, `isLoading` carrying it. Two hooks handed to [08](issues/08-refresh-and-caching.md): the caption may take a freshness suffix, and the no-toast rule holds only while a failed fetch replaces the card.

- [Refresh and caching behaviour](issues/08-refresh-and-caching.md) — **No cache**: `usePromise`, cold fetch every launch, because the command is opened at the moment something changed, so a cache would serve the wrong answer at the highest-value moment. That kills the ticket's where/how-long/how-signalled sub-questions by elimination, and closes **both of 09's hooks, neither taken**: the freshness suffix is declined (any relative label needs a `setInterval` or it becomes the lie it was added to prevent), and the no-toast rule becomes **unconditional**, because a refresh that fails on a healthy card **replaces** it with 09's failure card. One refresh semantic everywhere — full chain, trace then geo, even from the partial card, since a geo-only retry would assume the IP hasn't changed, the one assumption this extension exists to distrust. The card holds in flight under `isLoading`; ⌘R mid-fetch **aborts and restarts** (`usePromise({ abortable })`), without which a slow first response can overwrite a faster second — the only way to show a wrong IP with no fetch having failed. **The refresh race is resolved by comparing IPs**: same IP → the location line never moves; different IP → the card drops to 07's `ip-only` and refills as a cold start does, so a new IP is never shown beside the old IP's city. **No automatic retry** — one attempt each, since 04's states and 05's degrade are defined on a single outcome; 09 already made Refresh primary on both failure cards, so the retry is the design, just manual. **No timers anywhere**: no auto-refresh, no interval, no focus-refresh. One cost accepted knowingly — a refresh returning the same IP shows almost nothing but the loading bar.

- [What "done" looks like for the build session](issues/11-verification-story.md) — **vitest, 11 fixture cases over three pure functions, and a two-stage "done".** The ticket's premise was wrong: 90 corpus extensions ship vitest, 37 jest, so a runner is unremarkable, and with no CI here it costs one devDependency and one config file. The seam is **pure functions over already-fetched material, no injectable `fetch` anywhere** — `parseTrace(status, body)`, `parseGeo(json)`, and a new `nextState(prev, trace)` that makes 08's refresh-race rule a testable reducer; the fetch wrappers stay three-line `catch`es, so `unreachable` is the one branch with no fixture. Taking **status** into the parse is what lets the "2xx but not a trace" case be tested at all. Coverage is stated as a **rule** — one case per union member, plus a named test per known trap — so a later branch drags its own test in. Fixtures are **real captured bytes** embedded in the spec (tests writable offline), `ip=` redacted to TEST-NET-3 so no personal exit IP lands in a Store-bound repo; the two synthetic ones are labelled as invented. 02's never-measured over-quota shape needs no fixture — 05 folded it into the single degraded state. **A second geo trap surfaced while capturing**: `?fields=` drops `success` from a *successful* body but keeps it on failure, so `if (!json.success)` fails every healthy lookup — the guard is `json.success === false`. Gate is `lint → type-check → test → build`, with `tsc --noEmit` added because `ray build` type-checks only the entry graph, never a `.test.ts`; tests are not chained into build. **Green is not done**: a headless agent closes stage 1, a human closes stage 2 — six states seen in Raycast (failure states forced by a documented one-line temporary-edit recipe, the ~0.4s progressive render held open with a temporary `sleep`), four actions fired, two ⌘R checks. 08's abort ordering is the one thing neither tested nor observed — the guarantee is `usePromise({ abortable })`'s — so it becomes a **code-shape requirement** instead: both fetches must receive `AbortSignal.any([hookSignal, AbortSignal.timeout(5000)])`.

- [Write the handoff spec](issues/10-write-spec.md) — **[spec.md](spec.md) exists, `ready-for-agent`. The map is complete.** Eleven decisions collapsed into one buildable document — 39 user stories, eleven implementation decisions, eleven fixture cases with their bytes, a two-stage acceptance section. Carried verbatim as required: the manifest, both card markdowns, all five copy slots, the three provenance footers, the action table, the `nextState` transitions, the fixtures, the temporary-edit recipe. Deviates from the `/to-spec` template on two counts, both deliberate — it keeps file paths and code (the fixture bytes cannot be paraphrased without costing the build session a network round trip and losing the redaction convention), and it adds an **Acceptance** section, because 11's "green ≠ done" split is a definition of done rather than a testing decision. Three things surfaced only in assembly: `vitest` and the new scripts folded into 06's manifest (fixed before 11 existed), the two trap spellings collected in one closing section, and 04's attribution decision assigned to the README, which no ticket had done.
