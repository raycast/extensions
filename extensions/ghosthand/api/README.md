# API contract

`ghosthand.openapi.json` was retrieved on 2026-11-05 from the official documentation's [OpenAPI source](https://ghosthand.dev/api/openapi.json). This is the `openapiSpec` referenced by Ghosthand's API pages. The API version is `1.0.0`.

`src/lib/api.generated.ts` is generated by `openapi-typescript`; request bodies and response types derive from its schema definitions. Boundary checks reject malformed responses before rendering or claiming success.

To validate against an installed daemon, retrieve the exact specification it serves:

```sh
curl --fail --unix-socket "$HOME/.ghosthand/daemon.sock" \
  http://localhost/v1/openapi.yaml -o /tmp/ghosthand.openapi.yaml
npx openapi-typescript /tmp/ghosthand.openapi.yaml -o /tmp/ghosthand-api.generated.ts
```

Review contract differences before replacing the snapshot. Regenerate the checked-in types with:

```sh
npm run generate:api
npx tsc --noEmit
npm test
```

The machine used for initial implementation did not have Ghosthand installed or a daemon socket, so the published official specification was used. A follow-up live check on 2026-11-05 verified that every used endpoint matches the installed daemon's specification; schema differences only affect explanatory text and unused fields. No undocumented endpoints or inferred device fields are required. `PhoneStatus.id` is the preview ID; `captureId` is the lease acquisition ID. Local-only commands intentionally exclude `remotePhones`.

The task stream follows Ghosthand's documented [AI task endpoint](https://ghosthand.dev/api/post-v1-leases-lease-task) and the [AI SDK UI message stream protocol](https://ai-sdk.dev/docs/ai-sdk-ui/stream-protocol). Input streams use Ghosthand's separate `log` / `result` / `error` event protocol.
