How Your Watchlist Extension Works

You vibe-coded this. An AI wrote it. Now let's make sure you own it — every file, every connection, every design decision, explained from first principles.

The big picture

Your extension has three layers. Data lives in a Markdown file. A TypeScript module reads and writes it. React components (using the Raycast API) render it and handle user input.

Movies.md → media-data.ts → media.tsx → Raycast UI
User types a title → cinemeta.ts → add-media.tsx → media-data.ts → Movies.md
💡
Raycast extensions don't have a server or database. Your whole persistence layer is a single .md file on disk — elegant and Obsidian-friendly.

File by file

📄 media-data.ts — the data layer

The backbone. It knows nothing about Raycast or React. Its only job is to read and write Movies.md as a structured Markdown table.

Key exports:

  • loadMedia() — returns { watchlist, watched }
  • addItem(it, section) — inserts a row, creates the header if missing
  • markWatched(title) — splices the row out of Watchlist, inserts into Watched
  • updateItem(title, section, patch) — overwrites one row in-place
  • removeItem(title, section) — deletes the row
🔑
Key insight: all mutations are "read the whole file → splice lines → write the whole file." This is safe because Raycast extensions run one command at a time — no concurrency risk.

🎬 cinemeta.ts — the search API

A thin wrapper over Stremio's Cinemeta API — IMDb-backed, no key needed, no account needed. Two endpoints are used: 

// Search results (a list)
GET /catalog/movie|series/top/search={query}.json

// Full metadata for one title
GET /meta/movie|series/{imdbId}.json

searchAll() fires both in parallel with Promise.all and concatenates movies first. Each result is normalised into a SearchHit — a clean interface your UI can trust.

📋 media.tsx — the main list view

The default command. Renders two sections (Watchlist / Watched) with a sidebar detail panel. Key state: 

const [watchlist, setWatchlist] = useState<MediaItem[]>([]);
const [watched,   setWatched]   = useState<MediaItem[]>([]);
const [descs,     setDescs]     = useState<Record<string, string>>({});
const [filter,    setFilter]    = useState<Filter>("all");
const [showDetail, setShowDetail] = useState(true);

descs is a lazy cache of plot descriptions fetched from Cinemeta. The second useEffect fetches up to 20 at a time — only for items that have an imdbId and aren't already in the cache.

⚠️
The descs effect lists descs itself as a dependency. This is safe only because it immediately bails out when there's nothing new to fetch (if (all.length === 0) return). Without that guard, it would loop forever.

➕ add-media.tsx — the search & add flow

A separate command (and also reachable via ⌘N from the main list). It debounces the search input by 320 ms using setTimeout + useRef(seq) to cancel stale requests: 

const seq = useRef(0);
const mine = ++seq.current; // increment before async work
// … later, inside the async callback:
if (seq.current === mine) setHits(res); // only update if still relevant

This pattern (a monotonic counter) is the idiomatic way to avoid stale async results in React without reaching for a full abort-controller per request.

⭐ rate.tsx & ✏️ edit.tsx — small forms

Both push a Form onto the Raycast navigation stack. rate.tsx handles moving an item from Watchlist → Watched (with an optional rating/notes). edit.tsx patches any field on an existing item via updateItem(). Neither holds state beyond the form values — all persistence goes through media-data.ts.

The Markdown table format

Your data store is a human-readable Markdown table in Movies.md. Each row is one media item: 

| ✓ | Poster | Title | Type | Year | Director | Genre | IMDb | Mine | Notes |
|:-:|:-:|---|:-:|:-:|---|---|:-:|:-:|---|
| ☐ | ![\\|55](https://…poster.jpg) | [Dune](https://www.imdb.com/title/tt1160419/) | Movie | 2021 | Denis Villeneuve | Sci-Fi | 8.0 | | |

media-data.ts parses this by hand — no external library. The tricky parts are handled by two helpers:

splitRow()

Splits a pipe-delimited row while respecting \| escape sequences inside cell values.

sectionBounds()

Finds the line range for a ## Watchlist or ## Watched heading, so mutations never touch the wrong section.

layoutOf()

Detects whether the table already has a header row + divider, so it can insert one when the section is empty.

parseTitle()

Extracts the plain title and IMDb ID from a Markdown link like [Title](https://…/tt1234567/).

Data flow: adding a movie

Here's what happens when you search for "Dune" and press Enter:

  1. Keystroke in add-media.tsx triggers the debounced effect. After 320 ms of silence, searchAll("Dune") is called.
  2. cinemeta.ts fires two parallel requests to Cinemeta — one for movies, one for series — and joins the results.
  3. User picks a result. choose(hit, "Watchlist") is called. It first calls exists() to prevent duplicates, then detail() to grab the full metadata.
  4. addItem() in media-data.ts reads Movies.md, inserts a new table row under ## Watchlist, and writes the file back.
  5. Back in media.tsx, the onAdded callback fires, which calls refresh() → loadMedia() → state update → re-render.
