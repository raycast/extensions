The engine fix · src/engine.ts

What was wrong: execSync(`npx ctx7 library "Claude Code" "${query}"`) — the library name was hardcoded, so every prompt searched the Claude Code docs corpus and the engine returned the first line matching a command verb. For non-Claude-Code prompts this produced confidently wrong commands.

1. Derive the library name from the prompt

const STOPWORDS = new Set([
  "a","an","and","as","at","be","by","for","from","in","into","is",
  "of","on","or","the","to","via","with",
  "install","installing","configure","config","set","setup","create",
  "make","use","using","run","show","list","find","get","all","my",
  "globally","global","official",
  "cli","tool","command","line",
  "macos","linux","windows","ubuntu","mac","debian",
  "current","directory","this","that",
]);

function deriveLibraryQuery(prompt: string): string {
  const tokens = prompt
    .toLowerCase()
    .replace(/[^a-z0-9@/\-_.\s]/g, " ")
    .split(/\s+/)
    .filter((t) => t.length > 1 && !STOPWORDS.has(t));
  return tokens.slice(0, 4).join(" ").trim();
}

"install bun on macOS" → "bun" · "install Claude Code globally" → "claude code" · "install GitHub Copilot CLI extension" → "github copilot extension".

2. Reject topically-unrelated Context7 hits

function isTopicallyRelevant(title: string, prompt: string): boolean {
  const lowerPrompt = prompt.toLowerCase();
  const lowerTitle = title.toLowerCase().trim();
  if (!lowerTitle) return false;
  // Whole-phrase match — strongest signal.
  if (lowerPrompt.includes(lowerTitle)) return true;
  // Otherwise every non-stopword title token must appear in the prompt.
  const titleTokens = lowerTitle.split(/[\s\-_/]+/)
    .filter((t) => t.length > 1 && !STOPWORDS.has(t));
  if (titleTokens.length === 0) return false;
  return titleTokens.every((t) => lowerPrompt.includes(t));
}

findBestLibrary now returns { id, title } instead of just the ID, so the title can feed the topical guard. If the guard rejects, getContext7Answer returns null and the AI fallback runs — exactly the behaviour you'd want for any prompt that isn't about a library Context7 actually knows.

The one failure that remains

Hard #4 · install copilot-api + route Claude Code through localhost:4141
Got: 
npm i -g @copilot-api/cli && mkdir -p ~/.claude && \
printf '%s\n' '{"tools":{"claude_code":{"apiBaseUrl":"http://localhost:4141","authToken":"DUMMY_AUTH_TOKEN"}}}' \
  > ~/.claude/settings.json
Verdict: The shape is right (install + mkdir + write to ~/.claude/settings.json), but every identifier is wrong:
  • Package: @copilot-api/cli instead of copilot-api
  • Settings key: tools.claude_code.apiBaseUrl instead of env.ANTHROPIC_BASE_URL
  • Tool: printf > (clobbers) instead of jq (safe merge)
Claude Code actually reads ANTHROPIC_BASE_URL from the env field — the AI doesn't know that schema. Fixing this requires either web search (the engine already supports gpt-5-search-api when webSearch: true is set) or Context7 finding a Claude Code docs library that returns the canonical answer. Out of scope for the engine fix itself.
