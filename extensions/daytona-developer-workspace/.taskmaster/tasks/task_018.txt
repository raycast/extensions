# Task ID: 18
# Title: Replace Dashboard Mock Data with Live API Calls
# Status: done
# Dependencies: 1, 16
# Priority: medium
# Description: Refactor the Daytona Dashboard command to replace all hardcoded mock sandbox data with live data fetched using the Daytona SDK, ensuring the dashboard reflects the user's actual sandboxes.
# Details:
This task involves transitioning the 'Daytona Dashboard' command from a static, mocked-up state to a dynamic, data-driven component. The primary location for this change is the `src/commands/dashboard.tsx` file.

1.  **Identify and Remove Mock Data:** Locate the static array of sandbox objects within `dashboard.tsx`. This array currently contains placeholder data like `{ name: "python-analytics", status: "running" }`, `{ name: "web-scraper", status: "stopped" }`, and `{ name: "ml-experiments", status: "running" }`. This entire static array and any logic that consumes it must be removed.

2.  **Integrate Daytona Client:** Import the shared Daytona SDK client instance from `src/lib/daytona-client.ts` (established in Task 16).

3.  **Fetch Live Data:** Utilize Raycast's `usePromise` hook for asynchronous data fetching and state management (loading, data, error). The function passed to `usePromise` should be an async function that calls `daytona.sandbox.list()`.

4.  **Handle Loading State:** The `isLoading` property from the `usePromise` hook should be passed to the main `<List isLoading={isLoading}>` component. This will automatically display a loading indicator while the API call is in progress.

5.  **Render Real Sandbox Data:** Map the `data` returned by `usePromise` (which will be an array of actual Sandbox objects from the API) to `<List.Item>` components. Ensure the following properties are correctly mapped:
    *   `key` and `id`: Use `sandbox.id`.
    *   `title`: Use `sandbox.name`.
    *   `accessories`: Use `sandbox.status` to display the current state (e.g., 'Running', 'Stopped') with an appropriate colored tag or icon.
    *   `actions`: Ensure existing actions (like those from Tasks 12, 13, 17) are correctly attached to these dynamically generated items.

6.  **Implement Error and Empty States:**
    *   If the `usePromise` hook returns an error, display a user-friendly message using `<List.EmptyView icon={Icon.Warning} title="Failed to load sandboxes" />`.
    *   If the API call succeeds but returns an empty array, use `<List.EmptyView icon={Icon.Desktop} title="No Sandboxes Found" description="Create a new sandbox using the Daytona CLI or web UI." />`.

# Test Strategy:
1.  **Loading State Verification:** Launch the 'Daytona Dashboard' command. Verify that the Raycast loading spinner is displayed immediately and disappears once the API call completes.

2.  **Empty State Verification:** With no sandboxes configured in the target Daytona instance, run the command. Confirm that the 'No Sandboxes Found' empty view is displayed correctly.

3.  **Populated State Verification:**
    *   Create at least two sandboxes via the Daytona CLI: one in a 'running' state and one in a 'stopped' state.
    *   Launch the command and verify that both sandboxes appear in the list.
    *   Confirm that the names are correct and the status accessories accurately reflect their state (e.g., a green tag for 'running', a red tag for 'stopped').

4.  **API Error Handling:**
    *   Temporarily invalidate the API key in the settings (from Task 14).
    *   Launch the 'Daytona Dashboard' command.
    *   Verify that the 'Failed to load sandboxes' error view is displayed instead of the list.
