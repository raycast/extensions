# Native helper provenance

Both executables are built from the Swift sources in this directory. There are no downloaded executables or third-party Swift dependencies.

- `assets/apple-translate`: `Engine.swift` + `Translate.swift`; reads one JSON request on stdin and returns JSON on stdout.
- `assets/Apple Translate.app/Contents/MacOS/AppleTranslate`: `Engine.swift` + `Window.swift`; an optional larger AppKit/SwiftUI window, opened only by an explicit extension action.
- Architecture: arm64 only; deployment target: macOS 26.4.
- Frameworks: Apple's AppKit, SwiftUI, Foundation, NaturalLanguage, and Translation.
- Signature: ad hoc, generated by `codesign --force --sign -`. No developer certificate or private signing key is needed for the documented build.
- Build toolchain used for these artifacts: Apple Swift version 6.3.3 (swiftlang-6.3.3.1.3 clang-2100.1.1.101).

## Rebuild

On an Apple Silicon Mac with Xcode Command Line Tools and the macOS 26.4+ SDK:

```sh
npm run build:native
npm run test:engine
npm run test:native
```

The exact compiler and signing commands are in `scripts/build-native.mjs`. The script also generates the app's Info.plist and copies the icon. Normal Raycast JavaScript builds use the included helpers, so users and non-macOS JavaScript build jobs do not need a Swift toolchain.

## Data flow

The CLI receives user text through a pipe, checks the input size and installed language availability, and uses `TranslationSession(installedSource:target:preferredStrategy:)`. It never constructs a shell command from source text. The extension has no hosted translation endpoint, credential access, or telemetry.
