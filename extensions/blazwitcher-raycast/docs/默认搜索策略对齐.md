# 默认搜索策略对齐 Chrome Blaz

2026-10-12。本次根据用户的 `/h ea.com` 截图差异，将 Raycast 默认业务策略改为 Chrome 扩展的标题与域名搜索。两端仍使用 `text-search-engine@1.6.0`；SDK 升级不是额外标题加分的来源，原 Raycast 在匹配后一直有自己的标题与紧凑度评分。

## 结果差异的来源

原 Raycast 会先单独搜索完整标题，失败后再搜索标题与完整 URL，并给精确标题、标题前缀和标题参与命中加分。因此 `React` 标题中的 `ea` 与 `github.com` 组合匹配 `ea.com` 时，会排到只有域名命中的 `ea.com` 之前。Chrome 使用标题与 host 的统一匹配、0.6 严格度以及命中段数排序，不存在这些业务加分。

同关键词不同结果也可能由读取来源引起：Raycast 原先默认最近 20,000 条且不限日期，Chrome 默认最近 14 天最多 1,000 条。本次同时对齐默认读取范围，但用户显式配置仍保持原值。截图只能证明可见结果不同，不能单凭截图断言 Profile 错误或数据库陈旧。

## 默认行为

| 环节         | 默认与 Chrome Blaz 一致模式                                             | 显式完整网址模式                                           |
| ------------ | ----------------------------------------------------------------------- | ---------------------------------------------------------- |
| 匹配字段     | `title.trim()` 与 `new URL(url).host`，不插入分隔符                     | 原始标题与完整 URL，保留换行分隔                           |
| 空标题       | 历史与书签保留原空标题；空标题标签不参与搜索                            | 使用 URL 作为标题回退                                      |
| 空格与严格度 | 合并命中间空格，然后用 0.6 严格度过滤                                   | 不合并空格，不增加严格度过滤                               |
| 标题偏好     | 无标题单独搜索、标题加分或长词重试                                      | 保留原标题优先、紧凑度加分与长词重试                       |
| 来源筛选     | 先按 `/t`、`/b`、`/h` 或下拉框筛选，再匹配、去重                        | 保留原完整网址匹配与来源排序                               |
| 去重         | 保留全部标签；非标签以相同原始标题或完整 URL 合并，按输入顺序保留第一条 | 全部来源按原标签、书签、历史优先级去重；单来源保留各条记录 |
| 结果排序     | 命中段数少的优先；同段数历史按访问时间降序；同段数书签保持顺序          | 保留原评分、来源与访问时间排序                             |
| 展示数量     | 默认各 10 条，可配置 1–20；空查询同样适用                               | 按配置数量截断，再参与原 50 条分页                         |
| 最优建议     | 提取最终排序前 N 条，默认 2，支持 1–10                                  | 同样使用配置的 N 条                                        |

Chrome 后台先发送标签，再发送历史、书签。Raycast 默认固定这个顺序，异步文件读取先完成哪一个不会改变重复记录的保留方。索引继续每 250 条让出执行并检查取消；SDK 拼音映射缓存按 5,000 个 UTF-16 单元控制。局部刷新只替换一个来源，模式切换重建索引并使旧结果引用失效。

启动预览会按当前历史日期范围再次过滤，避免从此前不限日期的缓存临时显示旧记录。历史和书签读取中的空标题不再自动变为 URL；完整网址模式在索引内恢复这一旧行为。

新增原生搜索参数：历史时间范围、读取上限、历史和书签显示数量、最优建议数量、英文连续匹配。两种模式均传入 SDK 的 `isCharConsecutive`，默认关闭；开启后 `rct` 不匹配 `React`，中文拼音首字母仍可用。显示上限包含建议区中的该来源记录，建议不额外增加结果。完整网址模式全部来源先去重，再限额。

## 自动验证

新增回归先复现旧行为失败，再验证新默认与显式增强模式，包括：域名排名、过于分散的模糊命中过滤、host 与路径边界、标题 trim 与范围、词序、单来源和空查询去重、10 条展示上限、局部来源替换、模式切换与旧引用、历史时间范围、启动缓存范围以及 host 用户信息定位。旧全文网址、Unicode 与内存覆盖保留，并显式选择 `full-url` 模式。

使用 Chrome 测试工作区的 `scripts/compare-domain-query.ts`，动态加载两端实际搜索源码及各自实际安装的 SDK，仅使用 5 条公开历史样本，没有读取真实 Profile 或执行 UI：

- 修复前 `/h ea.com`：两端同一候选集合、都命中同 4 条，但精确 `ea.com` 在 Chrome 排第 1、Raycast 排第 4。
- 修复后：两端同匹配集合、同完整排序，精确 `ea.com` 都第 1；最优建议同为精确域名与 React 记录。
- 同命中段数的 `/h Search`：两端均为较新历史在前。

这证明公开样本上的源码策略差异已修复，不把 CPU 对比视为真实双端 UI 验收。PR 附有明确标注的公开样本排序图与原生搜索设置截图。

## 验收边界

Raycast 当前 JXA 标签采集没有 Chrome `lastAccessed` 字段，无法保证非激活标签的最近使用次序相同。只在真实元数据存在时使用 `lastAccessed`；缺失时保持采集顺序，不用历史访问时间伪造标签时间。多个窗口的激活标签以稳定比较器处理，不复制 Chrome 的非对称 active 比较器。

Raycast 不知道 Chrome Blaz 自身扩展的运行时 ID，因此无法像 Chrome 侧按该 ID 排除自身扩展页；默认已排除空标题、空 URL 和 `chrome://` 标签。Profile 选择、用户自定义读取范围、Chrome 可选连续匹配或展示数量设置，也会使跨端结果不同。两端默认设置的源码语义对齐，不表示跨端所有自定义配置自动同步。

公开 fixture 比较未读取个人 History。构建已导入本机并通过 CUA 搜索与参数保存、重开单点验证，仍未完成双端 Midscene Case。完整自动检查包含类型、回归测试、格式和构建；验证结果见 PR。

移除“来源快捷键初始预设”，统一通过命令内的 `⌘K → 快捷键设置` 修改。新用户默认使用 `⌘⇧0/1/2/3` 切换来源，原有 LocalStorage 中的自定义绑定和停用设置继续保留。
