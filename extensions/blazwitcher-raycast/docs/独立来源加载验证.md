# 书签与历史独立加载

## 问题与改动

统一搜索原先先读取全部所选配置的书签，之后才开始读取历史。书签读取尚未完成时，即使历史数据库可立即返回，历史来源也只能一直等待。

配置发现完成后，以 `Promise.all` 独立读取书签与历史，各来源完成后发布自己的结果。每个来源内部仍按配置顺序读取，避免同时启动所有配置的读取。标签读取、generation 校验、错误隔离、历史排序和合并后的总上限保持原有约束。

## 2026-09-20 验证

- 回归测试挂起书签读取，断言历史已经加载完成并可以搜索：修改前失败（历史仍为 loading），修改后通过。
- 共新增 5 项测试：慢书签/慢历史双向隔离、独立入口不读取无关来源、离开命令后丢弃两路迟到结果、书签失败隔离及多配置历史总上限。
- `npm run check` 通过：33 项测试、类型检查、ESLint、Prettier 和 Raycast 构建。
- `npm run test:local` 通过本机 Chrome 书签/历史读取和拼音搜索；只输出计数和耗时，没有输出私人标题和完整 URL。
- 真实 Raycast 开发版本：统一入口 `/h github` 返回历史结果，再改为 `/b github` 返回书签结果，保留原生单栏及操作入口。
- 可控慢来源场景由服务层测试验证；真实 UI 冒烟没有人为拖慢用户数据文件，也不作为固定性能提升比例的证据。
